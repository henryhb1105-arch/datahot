Microsoft Entra Agent ID 与 Dataverse 代理用户公开预览

微软宣布推出 Microsoft Entra Agent ID 与 Dataverse 代理用户的公开预览，为 AI 代理提供专属身份基础。该方案允许组织为每个代理分配独立身份以访问 Dataverse，配置相应安全角色，并审计代理活动。这有助于在人与自动化代理之间实现更清晰的权责分离，强化数据访问治理。

微软近日在 Microsoft Power Platform 博客上宣布，Microsoft Entra Agent ID 与 Dataverse 代理用户现已进入公开预览阶段。该功能由 Dataverse 安全与 Agent365 平台首席产品经理 Paul Liew 发布，旨在为日益普及的 AI 代理提供一个清晰、可管理的身份基础。

随着 AI 代理越来越多地参与日常业务过程——从研究潜在客户、更新记录到支持外联和后续跟进——组织需要明确了解是哪个代理在执行操作，以及它被允许做什么。微软此次推出的身份方案，正是为了解决这一治理需求。

Microsoft Entra Agent ID 在 Microsoft Entra 中扩展了专为 AI 代理设计的身份结构。过去，代理可能被视为匿名自动化，或共享一个通用应用身份，而现在组织可以为代理赋予一个可单独识别、符合策略的身份。Dataverse 代理用户则进一步将这一身份与 Dataverse 的数据访问场景绑定。

两者结合后，组织可以为每个代理分配访问 Dataverse 的专用身份，设置合适的安全角色，并保持对代理活动的可见性。这意味着团队可以以更审慎的方式引入基于代理的体验，并在人员、应用和自主代理之间建立更清晰的分隔。

这一预览版本的推出，反映了微软在 AI 治理和数据安全方面的持续投入。对于正在评估或已部署数据代理（Data Agent）的企业而言，身份管理是确保数据访问合规的关键环节。通过将代理纳入 Entra 的统一身份体系，企业能够更好地执行最小权限原则，并满足审计要求。

目前，该功能处于公开预览阶段，企业可以开始尝试为代理设置独立身份，并探索如何在 Dataverse 环境中实施更精细的访问控制。微软尚未公布正式商用时间表，但这一方向已为 AI 代理的安全治理提供了新的基础设施选项。

值得注意的是，该功能与 Power Platform 生态紧密集成，未来或将对基于 Dataverse 构建的 ChatBI、分析代理等场景产生直接影响。数据团队应关注其后续演进，以便在代理规模化落地时同步完善安全策略。
