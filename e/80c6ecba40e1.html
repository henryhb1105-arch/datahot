一、Data Agent市场分析

1. 市场定义

在经营分析会上，管理层追问利润下滑的原因。传统BI可以展示收入、成本和利润的变化，业务人员仍需继续拆分指标、核对数据，再由分析师制作图表和汇报材料。Data Agent开始接手这段分析工作：理解管理者提出的问题，寻找相关指标，调用数据和分析工具完成计算，并将原因线索与支撑依据整理成可复核的结果。

Data Agent是面向企业数据分析与决策支持场景，能够理解业务问题，调用企业数据、指标模型和分析工具，自主完成数据查询、指标计算、异常识别、原因分析及结果呈现，并以可复核的分析依据支持业务判断和后续工作的智能体应用。

Data Agent与传统BI的关系，是在既有数据基础上增加对分析任务的理解与执行。BI平台已经积累了数据连接、模型建设、指标管理、权限控制和可视化分析能力，为企业提供稳定的数据底座。Data Agent在此基础上理解自然语言提出的业务问题，规划分析步骤，并调用查询、计算和可视化工具。预先设计的报表适合持续监测固定指标，Data Agent则可以围绕临时出现的问题展开分析，两者共同构成企业的数据分析体系。

企业正在把Data Agent的重心从开放式问数转向边界清晰、结果可验收的分析任务。开放式问数侧重回答单次问题，任务型应用则要求Agent保持上下文、组织分析步骤并交付完整成果。这个变化使Data Agent从新的数据交互入口，进一步进入企业的日常分析工作。

2. 甲方终端用户

Data Agent的首批用户，通常是已经建设数据仓库、BI平台和指标体系，同时拥有高频分析需求的中大型企业。这些企业积累了较丰富的数据资产，业务人员对数据的使用也进入常态，但新增报表、临时取数和专项分析仍需要数据团队支持。业务需求持续增长，专业分析人员的服务能力难以同步扩张，Data Agent因而具备较明确的应用价值。

金融机构是较早形成规模化需求的一类用户。银行、保险和证券公司拥有大量经营与客户数据，分支机构和业务部门需要持续开展指标查询、业绩分析及风险监测。数据口径、访问权限和结果准确性直接影响业务使用，企业通常已经建立较成熟的数据治理和BI体系，具备进一步引入Data Agent的基础。

金融之外，能源电力、交通和制造等领域的大型集团也在积极探索Data Agent。这类企业组织层级较多，业务系统分布广泛，总部和下属单位需要定期开展经营分析。跨部门分析常要经历多轮取数、口径核对和材料汇总，Data Agent适合从这些高频、重复的任务切入。

Data Agent的使用者与建设者通常分属不同部门。业务部门负责提出分析问题，解释指标含义，并核验结果与实际经营情况的一致性；数据与技术部门负责接入数据、维护模型、配置权限和保障系统运行。双方共同参与，才能把业务语言转化为稳定的数据分析能力。

3. 甲方核心需求

企业通常从自然语言问数开始接触Data Agent。进入实际业务后，数据口径要一致，计算过程要经得住核对，异常还要继续追查，结果最终要进入看板、报告或业务表格。企业采购Data Agent，实质上是希望把一部分重复发生的数据分析任务交给Agent完成。

3.1 业务人员需要直接用业务语言获得可信答案，语义理解和数字计算都要可靠

企业中的业务概念往往带有特定口径。同样是“收入”，可能分别指签约收入、确认收入或回款金额；时间范围、组织层级和产品分类也会改变查询结果。Data Agent需要识别问题中的业务含义，将其映射到正确的指标、维度和筛选条件。

Data Agent的可靠性包含语义与计算两个层面。理解问题后，Agent还要调用经过治理的数据和计算引擎，并展示数据来源、指标定义及主要分析步骤。业务人员能够核对结果的形成过程，才会逐步将日常分析交给Agent。

3.2 一次问数只是入口，企业更看重Agent沿着异常继续分析，形成值得追查的原因线索。

业务人员发现收入下降后，通常会继续追问变化集中在哪些区域、产品或客户，进一步比较不同周期和业务单元。Data Agent需要保持分析上下文，主动选择趋势比较、维度拆解和指标关联等方法，将一个宽泛问题逐步收敛。

原因分析需要以数据证据为基础。Agent可以量化不同因素与指标变化之间的关系，呈现分析路径并形成可核查的原因线索，帮助业务人员缩小调查范围。

3.3 分析结果要进入下一步工作，看板、报告和业务表格需要直接形成。

数据查询完成后，企业仍要把结果制作成经营看板、分析报告或固定格式的表格。复制数字、调整图表和整理文字会消耗大量时间，也容易在转录过程中出现口径偏差。企业希望Data Agent能够根据任务要求组织内容，直接生成可继续编辑和使用的分析成果。

对于月度经营分析、管理层汇报和监管表格填报等重复任务，企业还希望将分析步骤和输出格式保存下来。后续数据更新后，Agent可以沿用已经确认的方法重新执行，让一次性的分析经验逐渐变成稳定的组织能力。

3.4 企业希望沿用多年积累的数据资产，让Data Agent建立在现有数据体系之上。

中大型企业通常已经建设数据仓库、指标平台和BI系统，并积累了数据模型、指标口径、分析报表及权限规则。引入Data Agent时，企业希望这些资产可以继续发挥作用，使Agent沿用已经确认的业务定义和计算逻辑，缩短重新整理数据的周期。

实际分析还会使用部门文件和个人表格。企业需要在权限允许的范围内，将这些临时数据与平台中的正式数据结合起来，完成预算比较、专项分析和临时报表制作。对既有资产的充分利用，有助于Data Agent更快进入业务，也能减少新旧分析体系之间的口径分歧。

3.5 Data Agent需要像企业数据系统一样被治理，才能从个人工具扩展为公共能力。

Data Agent可以调用的数据越多，权限和责任边界越重要。企业需要沿用现有用户身份和数据权限，让不同人员看到与其岗位相匹配的数据。Agent执行过哪些查询、调用过哪些工具、形成过哪些结果，也需要留下记录，支持问题排查和审计。

项目从少量用户扩展到多个部门后，企业还要关注响应速度、资源使用和结果稳定性，并建立持续评测机制。企业真实问题可以沉淀为测试集，用于观察语义理解、数字计算和任务执行的变化，让产品优化建立在可比较的结果上。

4. 厂商能力要求

Data Agent的交互入口很轻，用户说出一句业务问题就能启动分析；支撑这句话的，却是一套完整的数据分析体系。厂商既要让Agent理解企业的数据语言，也要保障计算可靠、分析可追溯，并将结果转化为业务人员能够直接使用的成果。评价Data Agent厂商，需要沿着数据准备、任务执行、成果交付和运行治理的完整链路展开。

4.1 厂商需要建立业务语义层，让Agent在企业的数据口径中理解问题。

企业数据分布在不同业务系统中，数据表、字段和指标名称往往按照技术逻辑组织。厂商首先需要具备广泛的数据连接与建模能力，将分散的数据组织成Agent可以使用的数据基础，并兼容企业已经建设的数据仓库、指标平台和BI模型。

在此基础上，厂商还要将指标定义、数据关系和业务知识组织成统一语境。业务人员提出问题时，Agent可以识别其中的指标含义和分析范围，并找到相应的数据模型。对于复杂场景，企业知识和部门文件也可以补充术语解释及业务规则，帮助Agent理解问题背后的经营环境。

4.2 可靠计算和可追溯分析，是Data Agent进入经营决策场景的门槛。

大模型适合理解问题、规划步骤和解释结果，具体查询与计算则需要交给数据库、BI引擎或专业分析工具完成。厂商需要合理划分模型与计算工具的职责，使指标计算沿用企业确认的规则，减少模型直接生成数字带来的不确定性。

分析结果还要附带可以核对的依据。厂商应当记录数据来源、筛选条件、指标口径和主要分析步骤，并允许用户查看或追溯。涉及复杂归因时，产品还要呈现指标关系和分析依据，便于业务人员继续核验。

4.3 Agent需要具备任务规划、工具调用和分析方法沉淀能力，把复杂问题拆成可执行步骤。

面对收入下降、成本异常等宽泛问题，Agent需要判断分析方向，形成任务计划，再调用查询、计算和可视化工具逐步完成分析。厂商需要支持多轮上下文管理，让Agent能够根据中间结果调整后续步骤，并在必要时邀请用户补充条件或确认分析范围。

开放性较强的任务适合由Agent动态规划，口径和步骤固定的任务可以通过流程加以约束。预置Skill为企业提供应用起点，更长期的价值来自企业将自身指标、分析方法和输出模板持续沉淀为Skill。厂商需要提供便于创建、测试、维护和复用Skill的机制，让项目经验逐渐转化为企业自己的分析资产。

4.4 厂商需要把分析结果做成可交付成果，并与企业现有工作链路衔接。

厂商需要支持Agent按照任务目标生成看板、分析报告和业务表格，并保留结果与指标、数据来源之间的关系。相关成果还应便于业务人员继续编辑和核对，进入经营会议、周期性汇报或业务报送等后续环节。

对于定期重复的任务，产品需要沿用已经确认的分析方法和输出格式，并随数据更新重新执行。Data Agent由此可以承担稳定、周期性的分析工作。

4.5 生产级治理与持续评测，支撑Data Agent在多个部门稳定运行。

厂商需要将企业原有的数据权限延伸到Agent，按照用户身份控制其查询范围，并对工具调用和分析过程保留记录。私有化部署、运行隔离和敏感信息保护等能力，也会影响金融、能源及大型集团的产品选择。

项目规模扩大后，厂商还要处理并发访问、计算资源和响应速度之间的平衡，并建立持续评测机制。企业真实问题可以沉淀为测试集，用于观察语义理解、数字计算和任务执行的变化。持续评测和优化，推动Data Agent从演示走向稳定运行。

二、代表厂商评估：思迈特软件

1. 公司介绍

广州思迈特软件有限公司（SmartBI）成立于2011年，是国家级专精特新“小巨人”企业，长期专注于企业数据管理、分析与决策支持。公司已服务超过6000家大型企业客户，覆盖60余个行业，客户包括金融机构、制造企业、能源企业和大型国央企。面向Data Agent市场，思迈特以多年建设的BI数据管理与分析为基础，推出白泽V5智能体数据决策分析平台。

2. 产品服务介绍

思迈特围绕企业数据管理和分析形成SmartBI Insight、SmartBI Eagle和SmartBI白泽等产品。Insight是一站式ABI平台，覆盖数据接入、数据与指标模型、报表、可视化分析和权限管理；Eagle面向数据资产运营。与Data Agent市场直接相关的产品是白泽V5智能体数据决策分析平台。

白泽V5内置数据洞察智能体，以Insight的数据连接、模型、指标和权限能力为底座。产品通过统一指标模型管理业务口径和计算规则，利用动态数据模型组织复杂的数据关系，并以企业知识库补充业务术语与分析背景。在此基础上，ReAct机制、多智能体协同和Skills体系负责规划任务、调用工具及组织分析过程，支持智能问数、异常识别、归因分析、多源融合、仪表盘生成、经营报告制作和复杂表格填报。

白泽V5支持接入企业已有的数据模型、指标、报表和权限体系，并提供私有化部署、细粒度权限控制、运行审计和隔离执行环境。Insight负责统一数据与分析底座，白泽V5在上层承接智能分析任务，两者共同服务于企业从传统BI向Data Agent演进的过程。

3. 厂商评估

思迈特的竞争特点来自三类长期资产。第一类是长期深耕企业级BI所积累的数据接入、建模、指标计算和权限管理能力，这些能力构成可供AI调用的企业级可信数据平台，为大模型与智能体提供口径统一、业务含义清晰、权限受控的数据；第二类是产品迭代与原厂实施并重的项目经验，能够把业务问题转化为数据模型、分析步骤和产品能力；第三类是较大规模的既有客户群，为新场景验证和产品打磨提供持续的真实反馈。

白泽V5将这些积累重新组织为Data Agent能力：大模型理解目标并规划任务，成熟的数据与计算引擎负责执行，高频项目经验进一步沉淀为Skill，生成的看板、报告和表格再回到企业分析体系中持续使用。这条路线尤其适合已经建设数仓、指标体系和BI平台，希望在保留既有投入的基础上引入智能体分析的大型企业。

3.1 BI时期形成的数据与计算底座，让白泽具备一条可核验的可信分析路径。

Data Agent要先理解业务问题，再给出准确的数据结果。思迈特将两类工作分层处理：大模型负责识别分析目标、规划步骤和组织表达；统一指标模型与动态数据模型确定指标口径及数据关系；具体查询和计算交由数据库及专业分析引擎执行。模型由此进入一套已经在企业分析场景中长期使用的数据链路。

白泽可以保留指标定义、数据来源、查询条件和主要分析过程。企业开展POC时，可以分别验证业务语言与指标的映射，以及查询计算的结果，出现偏差后也更容易定位问题。对于强调数字严谨性和审计要求的金融机构及大型集团，这种工程分工比单纯提高模型回答概率更有实际价值。

3.2 白泽复用Insight的数据、指标和权限体系，为已有BI投入提供低扰动的智能体升级路径。

中大型企业已经在数据仓库、数据模型、指标口径、报表和权限规则上投入多年。白泽建立在Insight的统一数据与分析底座之上，企业可以在完成资产盘点和适配后，让已有模型、指标及权限继续参与Agent任务，减少重新建设一套数据体系带来的时间和口径成本。

固定报表、自助分析和Data Agent可以在同一企业中长期并存。经营监测等稳定需求继续由既有BI应用承接，临时分析和重复发生的复杂任务逐步交给Agent。企业因此可以从少量高频、可验收的场景起步，待指标、步骤和输出标准稳定后再扩大范围，降低一次性切换带来的实施风险。

3.3 看板、报告和复杂表格能够回到既有分析体系，Agent交付的是可持续使用的工作成果。

思迈特将多年积累的报表和可视化能力转化为Agent可以调用的工具。业务人员可以用自然语言描述看板需求，也可以依据既有模板生成经营分析报告或完成复杂表格填报。生成的页面还可以发布回BI资源目录，重新打开时按最新数据刷新，并继续使用筛选、参数等分析能力。

这套机制把数据查询与后续制作连接起来。月度经营分析、管理层汇报和固定表格填报可以沿用已经确认的口径和模板重复执行，业务人员在现有工作环境中继续核对和修改。企业得到的是与数据源保持联系的分析资产，减少复制数字、重做图表和反复整理材料的工作。

3.4 真实项目中的共性需求被持续抽象为Skill，使交付经验能够进入产品并被后续场景复用。

白泽内置标准化的数据洞察智能体，并通过Skill扩展不同分析任务。思迈特在项目中识别具有共性的需求，再把分析方法、工具调用和输出要求转化为标准能力。例如，复杂表格填报最初来自保险客户的实际需求，经过项目验证后成为可复用的产品功能。产品迭代因此直接吸收一线场景，形成更贴近实际工作的能力。

思迈特既有客户基础为这套机制提供了较丰富的验证环境。新的Skill可以在金融、制造、能源等不同业务条件下检验适用边界，再根据反馈调整。对企业客户而言，预置Skill提供了更接近实际工作的起点；项目中形成的指标口径、分析步骤和输出模板也可以继续沉淀，减少后续场景从头定制的工作量。

3.5 产品快速迭代与FDE原厂交付结合，帮助企业跨过Data Agent从演示到业务使用的磨合期。

Data Agent项目通常同时涉及数据准备、指标梳理、场景选择、模型调优和用户反馈，单独交付一套标准软件很难覆盖这些工作。思迈特强调产品团队与实施团队协同，并形成FDE工作方式：项目人员与业务专家共同梳理需求，将业务语言转化为数据和产品要求，同时在现场完成快速验证与交付。

这种协作方式把场景选择、模型和指标梳理、问题集验证及版本迭代接在同一条实施路径上，项目中的共性需求再进入产品和Skill体系。对于仍处在早期落地阶段的Data Agent，持续迭代更有助于形成稳定、可扩展的应用。
