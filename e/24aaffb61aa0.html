Samsung Ads的ML团队将特征数据以Snowflake管理的Apache Iceberg表存放在Amazon S3，通过Amazon Cognito签发OAuth2令牌，把Snowflake Horizon Catalog联邦进AWS Lake Formation，让SageMaker AI与Athena等引擎直接读取同一份数据。方案用AWS PrivateLink和NAT网关打通VPC内的Glue连接，省去定时拷贝到S3的第二个管线和第二份副本，并统一由Lake Formation管控读取权限。

AI 逐段翻译

本文与三星广告（Samsung Ads）的机器学习平台工程师 Ajay Gunasekaran 共同撰写。

三星广告是三星电子的广告部门，其将特征数据保存在 Snowflake 中的 Apache Iceberg 表里。其机器学习（ML）团队在 Amazon SageMaker AI 上训练大规模模型，服务于触达三星智能电视和联网电视受众的程序化买方。连接这两者通常意味着按计划将数据复制到 Amazon Simple Storage Service（Amazon S3） 中。这会增加一条需要运维的管道、一份需要存储的副本，以及两套需要保持一致的权限。

团队可以不复制数据，而是将最终的管道阶段写为 Amazon S3 中由 Snowflake 管理的 Iceberg 表，并将其联合到 AWS Lake Formation 中。Amazon Cognito 提供 Snowflake 所信任的 OAuth2 令牌。随后两个应用程序都读取 Amazon S3 中的同一份数据副本，由 Snowflake 管理这些表，团队使用 Lake Formation 控制哪些主体可以读取它们。模型工程师可以选择适合每项训练任务的查询引擎，而无需复制数据或维护第二条管道。

在本文中，我们向你展示如何构建三星广告所使用的模式。你使用 Amazon Cognito 将 Snowflake Iceberg 表联合到 AWS Lake Formation，然后从 Amazon Athena 中查询它们。

解决方案概述

此解决方案使用 Amazon Cognito 签发用于机器对机器身份验证的 OAuth2 令牌，将 Snowflake Horizon Catalog 联合到 AWS Lake Formation。AWS Glue 连接在 Amazon Virtual Private Cloud（Amazon VPC） 内运行，通过 AWS PrivateLink 访问 Snowflake，并通过 NAT 网关访问 Cognito 令牌端点。随后 AWS 分析引擎在 Lake Formation 治理下查询由 Snowflake 管理的 Iceberg 表，无需维护表的第二份副本。下图展示了查询路径，从 Amazon Athena 经 AWS Lake Formation 和 AWS Glue 连接，到 Snowflake 和 Amazon S3。

图 1：使用 Amazon Cognito 将 Snowflake Horizon Catalog 联合到 AWS Lake Formation 的架构

工作流程的运行方式如下：

  1. 用户或应用程序在 Amazon Athena 中提交一条引用 Snowflake 目录中联合表的 SQL 查询。
  2. Athena 将目录解析和权限检查委托给 Lake Formation，后者对联合目录条目评估细粒度访问控制。
  3. Lake Formation 通过 AWS Glue Data Catalog 解析表引用，该目录保存 Snowflake 的连接配置并调用 AWS Glue 连接。
  4. AWS Glue 连接在私有子网中运行。它向 Amazon Cognito 令牌端点发送一个 client_credentials 请求，其中包含客户端 ID、客户端密钥和 scope。该请求经 NAT 网关和互联网网关发出，因为机器对机器令牌端点是公有的。
  5. Amazon Cognito 调用 Pre Token Generation Lambda 触发器（V3_0），该触发器添加 aud 声明，这是 Snowflake External OAuth 验证所要求的。Amazon Cognito 将访问令牌返回给该连接。
  6. 使用该令牌，AWS Glue 连接调用 Snowflake Horizon Catalog Iceberg REST 端点以获取表元数据。响应中包含 schema 以及 Amazon S3 中数据文件的位置。一个 Amazon Route 53 私有托管区域解析主机名，因为 Snowflake 端点服务不提供私有 DNS。请求通过 VPC 端点经由 AWS PrivateLink 传输。
  7. 该连接将元数据返回给 Lake Formation，后者生成临时的、限定范围的 Amazon S3 凭证并将其传递给 Athena。
  8. Athena 使用这些凭证从注册的 Amazon S3 位置读取 Iceberg 元数据和 Parquet 数据文件，运行查询并返回结果。

为什么选择 Amazon Cognito

AWS Glue 连接使用 OAuth2 client_credentials 授权模式进行身份验证，因此 Snowflake 所信任且支持该授权模式的提供方可以签发令牌。三星广告选择 Amazon Cognito 有三个原因：

  • 每次针对 Snowflake 的表查找都依赖于来自提供方的令牌，因此团队希望将其与解决方案的其余部分一起掌控。
  • 企业身份提供方通常由中央安全团队管理，因此每个新的机器对机器客户端都是一次跨团队请求。拥有用户池使其变为自助服务。
  • 每个应用客户端都是一个独立的机器身份，安全集成信任的是用户池而非单个客户端。因此，你可以通过一个集成服务多个工作负载，每个工作负载都有其自己的只读 Snowflake 角色。

先决条件

在开始之前，请确认你具备以下条件：

  • 在 Snowflake Horizon Catalog 中使用 CATALOG = 'SNOWFLAKE' 创建的 Snowflake 管理的 Iceberg 表，并带有一个指向 S3 存储桶的 外部卷。如果你没有，请参阅 Snowflake 文档中的为 Amazon S3 配置外部卷。

一个 AWS 账户，其中拥有在 AWS Lake Formation 中具有数据湖管理员权限的 AWS Identity and Access Management（IAM） 主体。该主体还需要创建 IAM 角色和策略、Amazon Cognito 用户池、AWS Lambda 函数、VPC 资源以及 AWS CloudShell 的权限。我们在本文中全程使用 AWS Command Line Interface（AWS CLI）命令。存放 Snowflake 管理的 Iceberg 数据文件的 Amazon S3 存储桶。一个拥有长期访问密钥的 AWS 用户，请在步骤 4 之后立即删除该密钥：

  • SYSTEM$AUTHORIZE_PRIVATELINK 需要来自 IAM 用户长期密钥的联合令牌，因为 sts:GetFederationToken 会拒绝角色会话凭证。Snowflake 会持久保存该授权，因此你之后可以删除密钥和用户，联合仍会继续工作。

步骤 1：部署 Cognito 用户池和令牌自定义 Lambda 函数

Snowflake External OAuth 验证要求每个访问令牌中都包含 aud 声明。OAuth2 client_credentials 授权并未定义该声明，因此由 Pre Token Generation 触发器添加它。此堆栈会创建用户池、机器对机器应用客户端，以及一个添加该声明的 Pre Token Generation Lambda 函数。该堆栈还会将应用客户端密钥以 AWS Glue 连接期望的格式写入 AWS Secrets Manager。然后它会生成您在步骤 3 中运行的 Snowflake SQL 语句。

  1. 选择 Launch Stack。
  1. 在区域选择器中，确认区域与您的 Snowflake 账户区域一致，然后选择 Next。
  2. 对于 Stack name，保留 snowflake-federation-oauth。将所有参数保留为默认值，然后选择 Next。
  3. 在 Configure stack options 上，保留默认值并选择 Next。
  4. 在 Review and create 上，选中 I acknowledge that AWS CloudFormation might create IAM resources with custom names，然后选择 Submit。
  5. 当堆栈状态为 CREATE_COMPLETE 时，选择 Outputs 选项卡。

您将在后续步骤中使用其中六个输出。

SnowflakeSecurityIntegrationSQL步骤 3

  3. 粘贴命令并运行。确认输出中的两个值。aud 声明与您的 Cognito 客户端 ID 匹配，且 scope 为 snowflake/catalog.read。

步骤 3：配置 Snowflake

在此步骤中，您将配置 Snowflake 以信任 Cognito 令牌，创建 Lake Formation 用于身份验证的服务用户，并授予该用户对表的读取访问权限。

  1. 在 Snowflake 工作表中运行以下语句，将三个占位符替换为步骤 1 中的 CognitoIssuerUri、CognitoJwksUrl 和 CognitoClientId 输出。SnowflakeSecurityIntegrationSQL 输出包含已填入您值的同一语句。CREATE 省略了 OR REPLACE，因此它会失败而不会覆盖现有集成。
USE ROLE ACCOUNTADMIN;

-- Return a row if the integration exists. If so, use ALTER SECURITY INTEGRATION instead of CREATE
SHOW INTEGRATIONS LIKE 'lakeformation_cognito_oauth';

CREATE SECURITY INTEGRATION lakeformation_cognito_oauth
  TYPE = EXTERNAL_OAUTH
  ENABLED = TRUE
  EXTERNAL_OAUTH_TYPE = CUSTOM
  EXTERNAL_OAUTH_ISSUER = '<CognitoIssuerUri>'
  EXTERNAL_OAUTH_JWS_KEYS_URL = '<CognitoJwksUrl>'
  EXTERNAL_OAUTH_TOKEN_USER_MAPPING_CLAIM = 'sub'
  EXTERNAL_OAUTH_SNOWFLAKE_USER_MAPPING_ATTRIBUTE = 'login_name'
  EXTERNAL_OAUTH_AUDIENCE_LIST = ('<CognitoClientId>')
  EXTERNAL_OAUTH_ANY_ROLE_MODE = 'ENABLE'
  EXTERNAL_OAUTH_BLOCKED_ROLES_LIST = ('ACCOUNTADMIN', 'SECURITYADMIN', 'USERADMIN', 'SYSADMIN');

Snowflake 通常从 session:role:<ROLE> 范围中获取角色，而 Amazon Cognito 自定义范围无法携带该范围，因为它们使用 resourceServer/scope 形式。因此该语句将 EXTERNAL_OAUTH_ANY_ROLE_MODE 设置为 ENABLE，这允许会话使用授予该服务用户的任何角色，因此请将该用户限制为单一角色。阻止角色列表还涵盖 SYSADMIN 和 USERADMIN，而 Snowflake 默认列表不包含它们。

  1. 创建只读角色和服务用户。将 LOGIN_NAME 设置为 CognitoClientId 输出，因为令牌的 sub 声明携带客户端 ID，且集成将 sub 映射到 login_name。
CREATE ROLE lakeformation_catalog_reader
  COMMENT = 'Read-only access for AWS Lake Formation catalog federation';

CREATE USER lakeformation_service_user_cognito
  LOGIN_NAME = '<CognitoClientId from Step 1>'
  DEFAULT_ROLE = lakeformation_catalog_reader
  TYPE = SERVICE;

GRANT ROLE lakeformation_catalog_reader TO USER lakeformation_service_user_cognito;
  1. 授予该角色对您希望联合的表的读取访问权限。有关 Iceberg REST Catalog API 所需的权限，请参阅 Snowflake 文档 中的配置访问控制。
GRANT USAGE ON DATABASE <database>
  TO ROLE lakeformation_catalog_reader;

GRANT USAGE ON SCHEMA <database>.<schema>
  TO ROLE lakeformation_catalog_reader;

GRANT SELECT ON ALL ICEBERG TABLES IN SCHEMA <database>.<schema>
  TO ROLE lakeformation_catalog_reader;

GRANT SELECT ON FUTURE ICEBERG TABLES IN SCHEMA <database>.<schema>
  TO ROLE lakeformation_catalog_reader;

注意： 仅联合包含 Snowflake 托管 Iceberg 表的架构。外部管理的表可能导致整个表列表失败。不支持转换表、从 Iceberg 兼容 Parquet 文件加载的表，以及源表对该角色不可访问的克隆。带混合大小写引号名称的表不会被联合，因为您在步骤 6 中创建的连接将 CATALOG_CASING_FILTER 设置为 UPPERCASE_ONLY。

当 Athena 读取联合表时，Snowflake 掩码和行访问策略不适用，因为 Lake Formation 提供 Amazon S3 凭证，而 Athena 直接读取 Parquet 文件。请将依赖这些策略的表排除在联合架构之外，或在 Lake Formation 中重新创建这些控制并对其进行测试。

  1. 接下来，找到您的外部卷写入的 Amazon S3 存储桶和前缀。您在步骤 5 中需要这两者。
DESC EXTERNAL VOLUME <your_external_volume>;

STORAGE_BASE_URL 包含存储桶和可选前缀。对于 s3://my-bucket/iceberg/，存储桶为 my-bucket，前缀为 iceberg。如果存储桶名称后没有任何内容，请在步骤 5 中将前缀留空。使用前缀更好，因为它将数据访问角色限制在该路径。如果 ENCRYPTION_TYPE 为 AWS_SSE_KMS，请记下 ENCRYPTION_KMS_KEY_ID 中的密钥，供步骤 5 使用。如果为 NONE，请在 Amazon S3 控制台中检查存储桶的默认加密。拥有 Iceberg 表的 Snowflake 角色必须保留对外部卷的 USAGE 权限，否则请求提供凭证的操作会失败。

如果存储桶使用客户托管 KMS 密钥，请将外部卷上的 KMS_KEY_ID 设置为完整密钥 ARN。然后将以下语句添加到密钥策略中，以便 Snowflake 用于 STORAGE_AWS_ROLE_ARN 可以读取加密文件。没有它，AWS Glue 连接会失败，并报错称没有会话策略允许 kms:Decrypt。

{
  "Sid": "AllowSnowflakeVolumeSession",
  "Effect": "Allow",
  "Principal": {
    "AWS": "arn:aws:sts::<account-id>:assumed-role/<external-volume-role>/snowflake"
  },
  "Action": [
    "kms:Decrypt",
    "kms:DescribeKey",
    "kms:GenerateDataKey"
  ],
  "Resource": "*"
}

步骤 4：在 Snowflake 中授权 AWS PrivateLink

Snowflake 需要证明你拥有该 AWS 账户，才会接受 PrivateLink 连接。你通过 AWS Security Token Service (AWS STS) 联合身份令牌提供该证明。你必须使用 IAM 用户的长期凭证调用 get-federation-token，因为 AWS STS 不支持使用来自代入角色的临时凭证调用它。

  1. 使用具有长期访问密钥的 IAM 用户生成联合身份令牌：
aws sts get-federation-token --name snowflake-privatelink --duration-seconds 900 --profile <iam-user-profile>

该令牌会出现在 SQL 语句中，因此 Snowflake 会将其保留在查询历史记录中。15 分钟的有效期限制了它的有效时长。

  1. 在你的 Snowflake 工作表中，传入你的 AWS 账户 ID 和上一条命令的完整 JSON 输出：
USE ROLE ACCOUNTADMIN;
SELECT SYSTEM$AUTHORIZE_PRIVATELINK('<aws-account-id>', '<full-federation-token-json>');

输出结果确认 Snowflake 已为你的账户授权 PrivateLink。

图 4：确认 PrivateLink 授权的 Snowflake 输出

  1. 获取步骤 5 中堆栈所需的两个值：
WITH cfg AS (SELECT PARSE_JSON(SYSTEM$GET_PRIVATELINK_CONFIG()) AS j)
SELECT j:"regionless-privatelink-account-url"::string AS privatelink_hostname,
       j:"privatelink-vpce-id"::string AS vpce_service_name
FROM cfg;

记录这两个值。privatelink_hostname 是 Snowflake PrivateLink 主机名，而 vpce_service_name 是端点服务名称。

授权成功后，删除临时 IAM 用户及其访问密钥。之后若要撤销 PrivateLink 访问权限，需要新的联合身份令牌，因此届时重新创建一个类似的用户。有关更多信息，请参阅 How to retrieve a Federation Token from AWS for PrivateLink Self-Service。

步骤 5：设置 VPC 和 PrivateLink 连接

此堆栈会创建指向 Snowflake PrivateLink 服务的接口 VPC 端点，以及将该 Snowflake 主机名解析到该端点的 Amazon Route 53 私有托管区。它还会创建端点与 AWS Glue 连接共享的安全组。将 Existing VPC ID 留空，它还会构建一个包含公有子网和私有子网以及 NAT 网关的 VPC。

要使用现有 VPC，请提供 Existing VPC ID 以及位于不同可用区的两个或更多私有子网 ID。这样堆栈不会创建任何子网，也不会创建 NAT 网关，因此请先确认三件事：

  • 你已在 VPC 上启用 DNS 解析和 DNS 主机名。
  • 私有子网具有指向 NAT 网关的 0.0.0.0/0 路由，AWS Glue 连接使用该路由访问 Amazon Cognito 令牌端点。Amazon Cognito 不支持 AWS PrivateLink，但由于两者位于同一区域，流量仍留在 AWS 网络上。没有此路由，堆栈仍会成功，但连接会在步骤 6 中失败。
  • 尚未有 privatelink.snowflakecomputing.com 的 Amazon Route 53 私有托管区与该 VPC 关联。同一域的第二个托管区会导致名称解析不可预测。

如果存储桶使用 SSE-KMS，堆栈会授予数据访问角色对你输入的密钥的 kms:Decrypt 权限。默认密钥策略已允许此操作。如果你的密钥策略未将访问权限委派给 IAM，请将该角色添加为密钥用户。

  1. 选择 Next，在 Configure stack options 上保留默认值，然后选择 Next。
  2. 在 Review and create 上，选择 I acknowledge that AWS CloudFormation might create IAM resources with custom names，然后选择 Submit。
  3. 当堆栈状态为 CREATE_COMPLETE（大约需要 5 分钟）时，选择 Outputs 选项卡并记录 PrivateSubnetIds、GlueConnectionSecurityGroupId、LakeFormationDataRoleArn 和 RegisteredS3Location。你将在步骤 6 中使用全部四个值。

NAT 网关和接口 VPC 端点会产生每小时费用和数据处理费用。有关更多信息，请参阅 Amazon VPC pricing。

步骤 6：在 Lake Formation 中注册并创建联合目录

其余设置是一系列 AWS CLI 命令。请在两个堆栈所在区域的 AWS CloudShell 中运行它们。

  1. 设置后续命令要使用的值。填入区域，以及步骤 1 和步骤 5 的堆栈输出。
REGION='<your Region>'
ACCT=$(aws sts get-caller-identity --query Account --output text)
PREFIX=snowflake-federation
CONN=$PREFIX-iceberg-connection
CATALOG=$PREFIX-catalog
S3_LOCATION='<RegisteredS3Location from Step 5>'
LFROLE='<LakeFormationDataRoleArn from Step 5>'
SECRET_ARN='<OAuthClientSecretArn from Step 1>'
TOKEN_URL='<CognitoTokenEndpoint from Step 1>'
CLIENT_ID='<CognitoClientId from Step 1>'
SCOPE='<CognitoScope from Step 1>'
SUBNET='<one subnet ID from PrivateSubnetIds in Step 5>'
SG='<GlueConnectionSecurityGroupId from Step 5>'
WORKSPACE_URL='https://<privatelink_hostname from Step 4>/polaris/api/catalog'
REMOTE_DB='<Snowflake database name, uppercase>'
SCHEMA='<Snowflake schema name, lowercase>'
QUERY_PRINCIPAL='<IAM role or user ARN that will run Athena queries>'
  1. 注册存放 Iceberg 数据的 Amazon S3 位置。这正是让 Lake Formation 能够向 Athena 颁发针对底层数据文件的限定范围凭证的原因。
aws lakeformation register-resource \
  --resource-arn "$S3_LOCATION" \
  --role-arn "$LFROLE" --with-federation
  1. 创建 AWS Glue 连接。此操作会把定义写入文件，然后创建连接。
cat > conn.json <<JSON
{
  "Name": "$CONN",
  "Description": "Snowflake Iceberg REST catalog through AWS Cognito.",
  "ConnectionType": "ICEBERGRESTCATALOG",
  "ConnectionProperties": {
    "INSTANCE_URL": "$WORKSPACE_URL",
    "ROLE_ARN": "$LFROLE",
    "CATALOG_CASING_FILTER": "UPPERCASE_ONLY"
  },
  "AuthenticationConfiguration": {
    "AuthenticationType": "OAUTH2",
    "SecretArn": "$SECRET_ARN",
    "OAuth2Properties": {
      "OAuth2GrantType": "CLIENT_CREDENTIALS",
      "TokenUrl": "$TOKEN_URL",
      "OAuth2ClientApplication": { "UserManagedClientApplicationClientId": "$CLIENT_ID" },
      "TokenUrlParametersMap": { "scope": "$SCOPE" }
    }
  },
  "PhysicalConnectionRequirements": {
    "SubnetId": "$SUBNET",
    "SecurityGroupIdList": ["$SG"]
  }
}
JSON

aws glue create-connection --connection-input file://conn.json
  1. 检查连接状态。AWS Glue 会异步验证。它会创建网络接口、完成与 Amazon Cognito 的 OAuth2 交换，并通过 AWS PrivateLink 调用 Snowflake Iceberg REST API。重复此命令，直到它返回 READY，这大约需要 5–10 分钟。
aws glue get-connection --name $CONN --query Connection.Status --output text

如果它返回 FAILED，请阅读原因并更正步骤 3 中的 Snowflake 配置。缺少安全集成、服务用户或授权是常见原因。

aws glue get-connection --name $CONN --query Connection.StatusReason --output text

然后先删除连接再重试，因为该名称会一直被占用。

aws glue delete-connection --connection-name $CONN
  1. 使用特权访问在 Lake Formation 中注册该连接。联合目录只能使用以这种方式注册的连接。
aws lakeformation register-resource \
  --resource-arn arn:aws:glue:$REGION:$ACCT:connection/$CONN \
  --role-arn "$LFROLE" --with-federation --with-privileged-access
  1. 创建联合目录，然后确认表通过它显示出来。
aws glue create-catalog --name $CATALOG --catalog-input '{
  "FederatedCatalog": {"Identifier": "'"$REMOTE_DB"'", "ConnectionName": "'"$CONN"'"},
  "CreateDatabaseDefaultPermissions": [],
  "CreateTableDefaultPermissions": []
}'

aws glue get-tables --catalog-id $ACCT:$CATALOG --database-name $SCHEMA --query 'TableList[].Name'
  1. 向将查询这些表的数据团队授予 Lake Formation 权限。创建目录的主体已经可以查询它。其他所有主体都需要显式授权，包括其他 Lake Formation 管理员。
aws lakeformation grant-permissions \
  --principal DataLakePrincipalIdentifier="$QUERY_PRINCIPAL" \
  --resource '{"Database":{"CatalogId":"'"$ACCT:$CATALOG"'","Name":"'"$SCHEMA"'"}}' \
  --permissions DESCRIBE

aws lakeformation grant-permissions \
  --principal DataLakePrincipalIdentifier="$QUERY_PRINCIPAL" \
  --resource '{"Table":{"CatalogId":"'"$ACCT:$CATALOG"'","DatabaseName":"'"$SCHEMA"'","TableWildcard":{}}}' \
  --permissions SELECT DESCRIBE

注意： 联合目录的目录 ID 是 :，而不是裸账户 ID。使用裸账户 ID 会改为授予对本地 AWS Glue Data Catalog 的权限，该操作会成功，随后使 Athena 返回访问被拒绝错误。

  1. 打开 Amazon Athena 控制台，然后选择 查询编辑器。如果这是您首次在此区域使用 Athena，请选择 设置，然后选择 管理，并为查询结果设置一个 Amazon S3 位置。
  2. 在左侧面板中，选择以下各项。
字段值
数据源AwsDataCatalog
目录您的联合目录，例如 snowflake-federation-catalog
数据库您的 Snowflake 架构名称（小写）
左右滑动查看 →
  1. 运行以下查询：
SELECT * FROM "<snowflake_schema>"."<snowflake_tablename>" LIMIT 10;

结果窗格中的行确认该联合可端到端正常工作，如下图所示。

要确认 Athena 读取的是 Snowflake 中的当前数据而非副本，请在 Snowflake 中插入一行并再次运行查询。新行会显示出来，且无需将额外数据移动到您的 AWS 账户中。

在 Snowflake 中删除表并不会撤销已授予该表的 Lake Formation 权限。在删除联合表时，请显式撤销这些权限。

清理

为避免产生未来费用，请删除您在按照本文操作时创建的资源。请在您的 AWS 账户和 Snowflake 账户中完成以下步骤。

AWS 账户

  1. 在 AWS Lake Formation 控制台上，选择 目录，选择您的联合目录，然后选择 操作 和 删除目录。
  2. 在 AWS Glue 连接仍然存在时，记录该连接创建的网络接口。按步骤 5 的安全组和 ICEBERGRESTCATALOG 描述进行筛选，可将列表限制为此部署。
SG='<GlueConnectionSecurityGroupId from Step 5>'
aws ec2 describe-network-interfaces \
  --filters "Name=group-id,Values=$SG" "Name=description,Values=*ICEBERGRESTCATALOG" \
  --query 'NetworkInterfaces[].NetworkInterfaceId' --output text | tr '\t' '\n' > glue-enis.txt

cat glue-enis.txt
  1. 取消注册并删除 AWS Glue 连接。请在删除堆栈之前执行此操作，因为当连接的网络接口仍占用安全组时，堆栈删除会失败。在 AWS CloudShell 中运行以下命令，并将区域、账户 ID 和连接名称替换为您自己的值。
aws lakeformation deregister-resource --resource-arn arn:aws:glue:<region>:<account-id>:connection/<glue-connection-name>
aws glue delete-connection --connection-name <glue-connection-name>
  1. 删除连接会释放其网络接口，但这些接口会在数分钟内保持“使用中”状态，并且 AWS Glue 不会移除它们。请等待每个接口达到“可用”状态，因为即使选中了强制分离，Amazon Elastic Compute Cloud (Amazon EC2)控制台的“分离”操作也会失败。以下脚本会检查您记录的每个接口，并在就绪时将其删除。
#!/bin/bash
while read -r eni; do
  [ -z "$eni" ] && continue
  for attempt in $(seq 1 20); do
    status=$(aws ec2 describe-network-interfaces \
      --network-interface-ids "$eni" \
      --query 'NetworkInterfaces[0].Status' \
      --output text 2>/dev/null || echo deleted)
    if [ "$status" = "available" ]; then
      aws ec2 delete-network-interface --network-interface-id "$eni"
      echo "$eni deleted"
      break
    fi
    if [ "$status" = "deleted" ]; then
      echo "$eni no longer exists"
      break
    fi
    echo "$eni is $status, checking again in 30 seconds"
    sleep 30
  done
done < glue-enis.txt
  1. 在 Lake Formation 控制台的 管理 下，选择 数据湖位置，选择已注册的 Amazon S3 位置，然后选择 操作 和 移除。
  1. 在 AWS CloudFormation 控制台上，先删除 snowflake-federation-network，然后删除 snowflake-federation-oauth。这会移除 VPC 终端节点、Amazon Route 53 私有托管区、安全组和 IAM 角色。它还会移除 Amazon Cognito 用户池、AWS Lambda 函数和客户端密钥。如果堆栈创建了 VPC、子网和 NAT 网关，它也会移除这些资源。

Snowflake 账户

  1. 打开 SQL 工作表并运行以下命令：
USE ROLE ACCOUNTADMIN;
DROP SECURITY INTEGRATION lakeformation_cognito_oauth;

USE ROLE USERADMIN;
DROP USER lakeformation_service_user_cognito;
DROP ROLE lakeformation_catalog_reader;
  1. 撤销您 AWS 账户的 PrivateLink 授权。这需要使用一个新的联合令牌，该令牌通过与设置时相同的方式、从具有长期访问密钥的 IAM 用户生成：
aws sts get-federation-token --name snowflake-privatelink --duration-seconds 900 --profile <iam-user-profile>
USE ROLE ACCOUNTADMIN;
SELECT SYSTEM$REVOKE_PRIVATELINK('<aws-account-id>', '<full-federation-token-json>');
  1. 确认该账户不再被授权：
SELECT SYSTEM$GET_PRIVATELINK_AUTHORIZED_ENDPOINTS();

删除联合目录和连接不会删除 Snowflake 或 Amazon S3 中的数据。它只会移除您 AWS 账户中的联合配置。

结论

在本文中，您了解了如何将 Snowflake Horizon Catalog Iceberg 表联合到 AWS Lake Formation，并从 Amazon Athena 查询它们。Amazon Cognito 处理用于机器对机器身份验证的 OAuth2 令牌。要将此模式扩展到其他工作负载，请在您的 Cognito 用户池中创建新的应用客户端，并创建相应的只读 Snowflake 角色。

要开始使用，请参阅 AWS Lake Formation 开发人员指南中的 Catalog federation to remote Iceberg catalogs 和 Federate to Snowflake Iceberg Catalog，以及 Snowflake 文档中的 External OAuth overview。
