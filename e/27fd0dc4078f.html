变更数据捕获是数据工程师在 Spark 上构建的最常见的事情之一，也是最繁琐、最难手工正确实现的事情之一。在我们之前的文章中，停止手工编写变更数据捕获管道，我们介绍了 Apache™ Spark 声明式管道 (SDP) 中的 AUTO CDC 如何通过几个简单的声明替换数百行脆弱 MERGE 逻辑来自动化 SCD 类型 1、SCD 类型 2 和快照 CDC。

随着管道需求的发展，工程师会遇到这些标准 CDC 模式难以解决的情况：

  • 处理乱序的双时态时间线
  • 在不破坏现有数据的情况下处理部分记录更新
  • 维护超出存储保留窗口的可审计性

今天，我们将 AUTO CDC 提升到新的水平，以解决这些实际挑战，并将这些功能扩展到开源 Apache Spark 4.2 中。

具有双时态 AUTO CDC 的双轴历史跟踪

标准 SCD 类型 2 表可以告诉你事实在现实世界中何时发生变化，但它们无法告诉你在任何给定时间点你的系统认为什么。

根据 SEC 规则 17a-4 和 FINRA 记录保存规则，公司必须能够重建在某个时间点存在的记录；仅 SEC 的记录保存检查自 2021 年以来已在 100 多家公司中开出了超过 20 亿美元的罚款。困难的往往是存储今天的价值。而是几个月后，回答：报告日期的参考数据是什么，当时我们的系统认为是什么。

标准 SCD 类型 2 跟踪一条时间线：事实何时发生变化。双时态 AUTO CDC 独立跟踪两条：

  • 业务时间（又称事件或有效时间）：事实在现实世界实际成立的时间。股票代码在周一开始可报告；国家代码在季度末退休。
  • 系统时间 （又称事务或处理时间）：记录系统了解数据的时间。周一的变化可能要到周三才能进入管道。

每个目标表都有四个系统管理的列： __START_AT 和 __END_AT 用于业务时间， __SYSTEM_START_AT 和 __SYSTEM_END_AT 用于系统时间。一个逻辑事实可以有多个物理行，每个业务版本/系统版本组合一行，这使得沿任一轴进行时间点重建成为可能。关键行为保证：事件可以在任一时间线上以任何顺序到达。

超越时间旅行：可在 VACUUM 后存活的可重现机器学习

当模型在参考数据或特征数据上训练时，可重现性意味着能够在几个月后重建模型使用的确切数据集，以进行审查或审计。直觉是使用 Delta Lake 时间旅行，但那是表文件历史记录的特性，不是永久记录。 VACUUM 会永久删除不再被最近版本引用的数据文件；一旦超过默认的 7 天保留窗口，训练时记录的 TIMESTAMP AS OF 可能会悄悄无法解析。双时态表将该历史存储为数据，而不是文件版本。 VACUUM 和 OPTIMIZE 会压缩文件，但绝不会触及逻辑历史，因此每个过去的业务或系统版本仍然是可查询的行。有两种方法可以从中获得可重现性：将两个 as-of 瞬间（业务和系统时间）记录为 MLflow 参数，并将训练查询固定到该信念状态：

AutoCDC 部分更新现已正式发布

并非所有变更数据捕获 (CDC) 源都会为更新发出完整行。相反，许多只发送更改的字段，将其他所有列表示为 NULL。如果没有特殊处理，这些 NULL 值可能会意外覆盖目标表中的现有数据。到目前为止，客户必须构建自定义逻辑来解决此行为。使用 AutoCDC 部分更新，现在可以自动处理。

部分更新扩展了 AutoCDC，允许更新事件仅修改列的子集。对于选定的列，传入更新中的 NULL 值被解释为“不更新”，而不是覆盖现有值。

这对于通过发出 NULL 来省略未更改值的 CDC 源特别有用。没有部分更新，这些 NULL 将覆盖目标表中的现有数据。

例如，假设目标表包含： (1, 'A', 20)

传入的更新事件包含： (1, NULL, 30)

默认情况下，AutoCDC 会将行更新为：(1, NULL, 30)。

启用部分更新后，name 中的 NULL 被视为“保持现有值不变”，结果变为：(1, 'A', 30)。

启用部分更新只需在 AutoCDC 定义中添加一个参数。您可以选择三种方式来指定应将哪些列视为部分更新：

  1. 应忽略 NULL 值的列列表：IGNORE NULL UPDATES ON columnList
  2. 不应忽略 NULL 值的列列表：IGNORE NULL UPDATES ON * EXCEPT (columnList)
  3. 一个源列名，每行可以不同：COLUMNS TO UPDATE

有关完整语法、示例和使用指导，请参阅部分更新应用文档。

我们继续致力于开源

Spark 声明式管道是开源的，因此其最广泛使用的流程类型也应该是开源的。我们首先将 AUTO CDC Type 1 的 Python API 贡献给 Apache Spark 4.2。

我们按照 Spark 其余部分的演进方式进行了贡献：作为一系列经过审查的提案和拉取请求，而不是一次性代码转储（请参阅SPIP 和 SPARK-56249）。乱序数据的正确性内建：一个小型辅助表跟踪来自提前到达的事件（如删除墓碑标记）的状态，重试的微批处理收敛而不是破坏目标，并且由于它基于 Spark 的流式和表抽象而非存储格式构建，因此可在 Delta Lake 和 Apache Iceberg 上运行。

下一步，公开进行：

  • 下一个版本中的功能： 我们已经将 SQL 接口（CREATE FLOW ... AS AUTO CDC INTO）合并到 master，它将在下一个 Apache Spark 版本中发布。
  • 高级管道语义： 正在开发 SCD Type 2 全历史管理、原生变更日志输入，以及防止 NULL 值覆盖目标数据的部分更新支持。
  • 可靠性与测试： 我们在扩展围绕乱序数据和幂等重试的自动化测试套件的同时，添加了 apply-as-truncate 功能。
