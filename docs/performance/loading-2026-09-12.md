# DataHot 加载性能优化方案与验收

关联 Issue #11，基线 main `45250e5874563c5f95e1c85c0d34cd36007617ba`。

## 基线与目标

2026-09-12，Lighthouse 13.4.1 / Chrome 152，移动端默认模拟慢速4G、CPU 4倍减速。首页和案例各3轮；图文详情3轮、文字详情1轮。该测试不代表中国大陆三网真实用户数据。

| 页面 | 基线 | 验收目标 |
|---|---|---|
| 首页 | 98分，LCP 1.9–2.0秒；约213KiB | 保持静态首屏，重复访问复用同版数据，筛选/搜索/返回位置正常 |
| 案例库 | 74–83分，LCP 4.5–9.1秒；2190KiB | 同配置3轮中位LCP ≤2.5秒，传输至少降低60%，原图查看和裁切不回退 |
| 图文详情14767d1f90cf | 两次CLS 0.327，一次0；约1MiB | 3轮CLS≤0.1；保留原文、原图与图表 |
| 文字详情 | 99分，LCP1.7秒；未播放仍请求约93KiB音频 | 不点击播放不请求音频，播放/暂停/进度正常 |

## 方案

1. 构建时生成同源 WebP 派生图。案例卡片使用400/800/1200宽度，正文480/960/1440，不放大原图；内容哈希包含原始字节与处理参数。来源图片字节不变，查看器和原文链接保持不变。已审核焦点区域生成对应裁切缩略图，标签和视觉比例保持原样。首张案例图片 eager/high，其他图片继续 lazy。
2. 将分享组件中控制顶部栏与文章边距的CSS提前到head。受控HTML分段实验准确复现线上CLS=0.3271968；相同断点与1.2秒间隔，改动后CLS=0。原自动诊断将位移关联到正文图片，但根因是文档尾部样式晚到，不能用“补图片宽高”替代根因修复。见本目录前后布局位移记录。
3. 首页/关注/收藏引用同一个内容版本化轻量JSON URL，首页和收藏从no-store改为正常HTTP缓存；首页和收藏脚本同时加内容版本号，避免CDN旧脚本继续强制请求。保留空闲预取和静态首屏，维持首次搜索响应。
4. 音频使用preload=none，用户播放时再读取。不新增第三方运行依赖，也不变更CDN账户规则。

## 验证与发布

- Python：派生图片小于原图、正确裁切、原图字节不变、内容变化失效、重复构建复用、不放大、路径边界、HTML中的首屏优先级与样式顺序。
- 链接校验扩展到srcset的每个候选，避免只有默认src有效而高DPR图片404。
- 浏览器：案例筛选/对比/全部案例阅读/原图、手机与桌面无横向溢出、收藏；首页同版本缓存/分页/搜索/返回；详情慢速分段加载无跳动及播放按需请求。
- 所有修改仅在Issue独立worktree。部署前更新main、重新生成与测试，比较最新线上事件/详情数量；统一Actions单写者发布。
- 源码提交不携带旧生成HTML或内容数据。派生图由构建产生，随Pages候选一起上传；发布后以普通URL核验manifest、资源和3轮Lighthouse。
- 若回滚，回退本Issue源码提交并通过同一Actions构建；原始图片未改动。
