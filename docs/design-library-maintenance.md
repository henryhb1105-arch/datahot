# 数据产品设计库：深度案例维护

关联：Issue #204 的设计参考深化阶段。不包含关注产品、X 自动采集或新的外部推送。

## 定位与内容单元

帮助设计 Data Agent、数据平台与 BI 产品的人，带着一个设计问题找到真实界面、看懂操作和反馈，再判断是否适合自己的场景。不是新闻数量榜，也不是漂亮截图集。

- 原有 18 个案例保留；其中 SageMaker Notebook、Databricks Genie、OpenSearch 深化。
- 新增 Hex Threads、Metabase Metabot、Wren GenBI Classic，共 21 个案例、6 篇深度拆解、23 个配图操作。
- Wren 明确为已 Sunset 的历史版本，不能写成当前产品能力。
- 三种纠偏方式的固定对照围绕“AI 给出结果后，用户如何修改和验证？”，不新增一级导航。
- 原始文章继续从原 URL 阅读；不更改速览、正文、发布日期或新闻流。

## 入库门槛

1. 先写一个具体设计问题，不能只写“某产品发布”。
2. 至少 3 个有截图证据的操作状态。顺序用于阅读，不代表完成了端到端实测；不同示例明确边界。
3. 每步写用户操作、可观察的系统反馈和截图看点。未显示生成结果时，不能写成生成成功。
4. DataHot 设计判断单独展示；写适用条件和代价，并指向支撑该判断的操作编号。
5. 记录来源、材料类型、版本/历史状态与核对日期。所有图片保留原始来源链接，不使用 AI 图片冒充产品界面。
6. 原文图要有合法可用的缓存来源；图片与运行脚本由本站提供，不新增 Google Fonts、国外 iframe 或在线模型依赖。外部出处可点开，但不是阅读案例的必需依赖。
7. 无法证明的功能标“未展示”，不写“产品没有”，也不把 UI 设计说明当作功能成功率评测。

## 后续选材建议（不是已开启的自动任务）

每周先检查 2–3 个候选，只有满足门槛才入库，数量不作硬指标。优先补齐与现有案例不同的设计问题：权限审批、任务中断恢复、指标语义确认、结果转成应用。候选来源优先官方文档、官方操作演示和作者一手实操；同一产品的新版本优先更新既有案例，避免重复堆叠。

对失效来源保留可核验的历史记录并标注，不能自动改成最新版本。若截图无法合法保存且外部访问受限，先保留候选，不凑成“深度案例”。

## 数据和页面

- 清单：`pipeline/design_studies.json`，schema `design-studies-v1`。
- 构建与证据校验：`pipeline/design_studies.py`。
- 新案例使用固定 slug 生成稳定 ID，页面为 `cases/<slug>.html`。不伪造新闻事件、不写入 `latest.json`。
- 新闻关联案例沿用 event_id 和缓存 figure_id。原有产品案例保留策略继续负责留存这些事件与原文图。
- 新截图存放于 `pipeline/assets/case-media/<slug>/`，构建后复制为同域 `case-media/`。
- `#step-N` 是稳定的操作深链；相关案例和对照直接链接到证据，不依赖登录。
- 收藏沿用已有设备端收藏，新增安全受限的 `detail_path` 字段；反馈和收藏分开，反馈不会自动触发推荐。
- 无 JavaScript 时显示全部步骤，原图与来源仍能直接打开。

## 既有案例的看图阅读与手机布局

- 其余 15 个既有案例由 `pipeline/case_readings.py` 生成 `cases/case-<event_id>.html`；代表图在前，其余图保持原文顺序。材料不足以证明连续操作时使用“配图”，不凑成操作教程。
- 所有原图、来源、原文 URL 与收藏 ID 保留；架构/方法参考、官方示意和社区截图继续注明材料性质。页面中的判断复用已有策展内容，不重写原文。
- `pipeline/case_visuals.json` 只登记人工检查过的截图重点区域、原始尺寸与说明。列表用 CSS 展示局部，详情在完整图片上标框；打开查看器始终是未经修改的原图。更换源图后必须重新核验尺寸与坐标。
- 手机端收起筛选说明与重复计数，保留搜索、设计问题、更多筛选和重置。固定对照及自选对比都按问题纵向展示产品，桌面继续用表格。

## 验收与发布

先在 Issue 留下租约声明，在隔离 worktree 修改。不可把本地构建产生的旧新闻输出覆盖远端。只合入对应源码、素材、测试与维护文档，由统一 Actions 从最新主线构建，通过防缩水检查后发布。

```sh
python3 -m unittest discover -s tests -v
node --test tests/*.test.js
python3 pipeline/build_site.py
python3 pipeline/check_links.py site
```

浏览器验收脚本 `tests/design-studies.browser.cjs` 连接 agent-browser 的本地预览会话（7204 端口），需要既有 Playwright 运行库。覆盖 320/390/430/700/1440px、15 篇看图阅读、6 篇分步阅读和 23 张操作图、首屏位置、原图查看、键盘/焦点、筛选、收藏往返、反馈、两种手机纵向对照、深色模式和无 JS；阻断全部非本地请求。原站匿名 UV 不用于验收。

上线用不执行 JavaScript 的 HTTP 检查确认新页面、素材、脚本和 sitemap 生效，同时检查历史事件没有异常缩水。可读性由本地浏览器证据验证，不用生产浏览器测试制造访问量。

本阶段衡量“是否能找到参考并完成一次设计判断”，不以卡片数量或点赞数宣称有效。后续可观察真实用户的案例打开、收藏和有帮助反馈，但不把自动验收行为记为用户使用。
