ClickHouse 的 Postgres 扩展如何处理 C/C++ 内存安全

ClickHouse 开发了 pg_clickhouse、pg_re2、pg_chdb、pg_stat_ch 等 Postgres 扩展，并将 C++ 引入原本用 C 编写的 Postgres，由此产生内存管理冲突。Postgres 采用 MemoryContext 与 palloc/pfree，并用基于 setjmp/longjmp 的 PG_TRY/PG_CATCH/PG_FINALLY 处理错误；C++ 则使用 new/delete 和异常，二者交互会跳过析构、触发未定义行为，未捕获异常还会导致进程 abort。各扩展采取不同策略：pg_clickhouse 完全移除 C++，用新的 C 库 clickhouse-c 替代 clickhouse-cpp，并包装为 pg-clickhouse-c 以整合 Postgres 逻辑、保持通用库复用。clickhouse-c 被设计为传输无关，支持 Native 协议之外的 Native 格式，使 HTTP 驱动复用大量编解码逻辑。

推荐理由：对数据库扩展、FDW 与数据集成组件的开发者有直接参考价值：它讲清 C/C++ 内存安全边界、错误处理和进程隔离的坑，可帮助避免崩溃与共享内存损坏。

亚马逊云科技确认中东部分区域数据不可恢复

亚马逊云科技确认，中东（阿联酋）me-central-1 的 mec1-az2 可用区及整个中东（巴林）me-south-1 区域中仅存于本地的资源和数据不可恢复；原因是无人机袭击导致损毁超出区域性多可用区服务的设计承受能力。公司称阿联酋其他可用区仍在恢复，巴林更多细节将在2027年初公布。Hacker News 讨论聚焦共同责任模型、跨区域备份、S3 区域级冗余边界及数据驻留义务。该事件说明云厂商冗余不等于跨区域灾备，企业需按合规与业务连续性要求设计备份和恢复策略。

推荐理由：数据从业者应关注云数据基础设施的容灾边界与共同责任模型，以及跨区域备份、数据驻留和合规对数据平台架构的约束。
