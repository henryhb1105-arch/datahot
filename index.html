ClickHouse托管Postgres用直接I/O加速备份

ClickHouse Managed Postgres 备份时需要从服务查询的 NVMe 盘读取全库并传到对象存储，默认缓冲 I/O 会污染 page cache，进而影响查询延迟。直接 I/O 跳过 page cache，测试中把备份期间查询延迟影响降低约三分之二，并减少约14% CPU，但会关闭内核预读。ClickHouse 按 RAID0 stripe 大小设置直接读取，并扩展 reader 数；在 48 vCPU、4 块 NVMe、467GB 数据库测试中，直接 I/O 备份未驱逐 40GiB 热数据，71 秒完成。

推荐理由：数据库备份与在线查询争抢 I/O 是生产环境常见痛点；该文给出 direct I/O、预读、RAID0 stripe 与 reader 数的可复现调优思路和量化收益，对数据平台与数据库从业者有直接参考价值。

Docker 沙箱套件规范：把 AI Agent 权限打包为 OCI 镜像

Docker 宣布将 Sandbox Kit Specification（Apache 2.0，现为 v3）提交给 CNCF，目标是把 AI Agent 可访问的资源变得和 Agent 本身一样可移植。该规范把 Agent、其工具以及所请求的主机、凭据和卷的类型化清单打包进一个普通 OCI 镜像，manifest 中只声明 vnd.docker.sandbox.kit.descriptor，因此可用 docker buildx build 构建、docker pull 拉取，并支持扫描、签名与 FROM 引用。权限被声明为带版本的类型化能力（如 com.docker.sandbox/network-policy@2、com.docker.sandbox/credential@1），凭据可由符合规范的运行时代理注入，沙箱内只保留哨兵值。Kit 仅提出权限请求、由宿主决定是否授予，Docker Sandboxes 是首个符合规范的运行时。

推荐理由：分析类 Agent 要真正落地，必须解决“它能碰哪些数据源、用哪些凭据”的可审查、可移植问题；该规范把 Agent 权限变成可版本化、可签名的 OCI 制品，并给出拒绝优先、凭据代理等具体机制，是团队设计 Agent 权限模型的重要参考。

Lakebase Postgres 基于分支的秒级恢复

Lakebase Postgres 通过计算存储分离和对象存储中的数据库历史实现基于分支的恢复：在指定时间点创建分支只是元数据操作，不再复制数据到新磁盘或重放 WAL。传统托管 OLTP 恢复需部署新实例、恢复快照并重放 WAL，数据库越大越慢，且故障切换无法应对已写入备库的错误写入。Lakebase 称恢复时间可降至秒级，即使数据库达到 100 TB，并简单到可由 Agent 执行。

推荐理由：数据从业者应关注托管 OLTP 恢复架构的变化：分支式恢复把小时级恢复压缩到秒级，并影响高可用、容灾和成本设计。
