原文

竞品监控总是半途而废？作者用 Workbuddy 和卖家精灵 MCP 打造了一套 7x24 小时自动化监控方案，双路分工解决反爬与数据延时难题，还能自动推送报告到飞书/企微。手把手教你从零跑通，让运营双手离开键盘。

之前分享过找亚马逊竞品的五步法，帮助很多卖家朋友精准狙击到竞品，那接下来要做的就是长期监控！

于是我又开发了一个「亚马逊竞品全域监控Skill」，可以帮大家实现7*24小时自动化跟踪竞品在站内+站外的情况。

今天用【Workbuddy+卖家精灵 MCP】，给大家演示怎么给竞品 ASIN 挂上定时任务，完成自动追踪站内变化与公开站外推广，并推送报告到飞书/企微。

市面上的竞品监控方案，普遍卡在哪里？

重新做这套工具前，我看了一圈市面上的竞品监控项目，主要有两个特点。

一是单纯靠浏览器自动化高频访问网页。

亚马逊反爬风控很严，连续直接抓取商品页极易触发验证码或拦截，跑几轮就会中断。

二是直接用第三方数据MCP作为唯一数据来源。

这些第三方数据MCP的底层数据更新会有延时，你无法通过MCP获取到页面最新信息，但他们积累的历史数据非常充分。

所以这次我做了双路分工：实时采集通路负责抓当下的页面指标与变动，卖家精灵 MCP 负责补充历史价格带、销量体量与关键词背景。

跑完一轮之后，核心会交付两份本地文件。

第一份是 Markdown/HTML 格式的监控报告。列出本轮采集状态、指标变化对照、市场背景参考和业务解读：

第二份是自动维护的本轮表和累计历史 CSV 表格，每次巡检完自动按轮次追加记录，方便后续用 Excel 筛选复盘：

在 WorkBuddy 里怎么跑起来？

实操核心思路很清楚：先接好数据源，手动跑通第一次采集生成监控档案模板，最后交给定时任务自动复跑。

1. 安装专家/技能

在【技能/专家】页面，搜索【新西楼/buluslan】，就会出现我的跨境电商全链路Skill，然后安装「亚马逊竞品全域监控专家」技能/专家。

同时欢迎大家加入「MBG 跨境AI实战圈」，这里聚集了跨境大卖、AI大神，来一起深度交流，跑通【跨境AI】的从0到1

2. 配置卖家精灵 MCP

我们做市场洞察、竞品分析和选品，必须要接入市场数据，才能得出有理有据的判断结论。

还是非常推荐大家接入卖家精灵的MCP，让AI具备直接调取亚马逊商品Listing、评论、品类市场数据的能力。

接入也很方便，直接在【连接器】搜索【卖家精灵】，就会出现【卖家精灵融合版】的接口，你通过这一个入口就能同时调用达人精灵/卖家精灵/优麦云的数据。

按照指引去官方获取APIKEY，回到这里填写保存就大功告成了！

如果有小伙伴对MCP的作用不了解，欢迎阅读我这篇MCP科普帖。

选品、广告、关键词数据从哪来？我整理了这份亚马逊卖家的数据MCP选型指南（附提示词和教程）

3. 手动执行首次采集，生成监控档案模板

第一次运行时，我们需要手动触发一次完整采集来建立基线档案，这里提供两种采集方式。

方式一：使用 WorkBuddy Computer Use 直接采集（零门槛免配 API）

Workbuddy近期推出的Computer Use功能，可以让AI直接操作你的电脑，模拟人工打开网页去获取信息。

官方指引：你说一句，它来点：WorkBuddy上线电脑操控能力

优点是方便，不需要自己配置乱七八糟的东西。

缺点就是速度比较慢，耗费额度比较多，而且要占用你的电脑窗口，抓取不是很稳定～

如果你要监控的竞品数量比较少，可以直接使用这个方式。

直接在对话框发送下面这段指令，让专家调用内置的电脑与浏览器操作能力完成首轮建档：

请使用「亚马逊竞品全域监控专家」，为美国站竞品[填入 2-5 个核心竞品 ASIN，]建立监控档案并完成首轮基线采集（保存至[你的本地工作区路径]）。 本次站内实时采集不调用外部商品 API，请直接使用 WorkBuddy 自带的 ComputerUse/ 浏览器能力打开商品页： 1. 先将亚马逊左上角配送地址切换为美国邮编10001并刷新确认生效（显示 USD 与10001）； 2. 按十项核心字段清单采集当前新品价格、Coupon 优惠原文、可售状态、BSR 排名、评分、评论数、标题、五点、Buy Box 卖家、父 ASIN 与当前选中规格（若遇验证码立即停止，不强行绕过）； 3. 结合卖家精灵 MCP 补充历史价格趋势与销量背景，生成首轮 Markdown 监控报告与标准 CSV 表格。

如果你尝试了两遍还没抓取成功，建议你采用下面的方式二！

方式二：接入 Bright Data 实时采集 API（适合多竞品高频稳定巡检）

我会更推荐接入一个第三方API服务，我自己习惯用的是Bright Data，你也可以换成自己喜欢的。

优点是采集量更大，运行更稳定，速度更快，还不占用我的电脑。

缺点就是，要付费咯，但我算了下价格也不贵，几毛钱一条吧。

关于数据采集这块，我之前也有过非常详细的介绍，推荐大家阅读！

一文讲透跨境电商爬虫：血测23款工具后，这是我的终极避坑指南

具体操作上，你需要先到对应的第三方网站上配好APIkey，然后把这个密钥保存到本地文件里。

然后复制下面这段提示词发给WorkBuddy，AI会自动生成专属的适配脚本并完成首轮采集。

请使用「亚马逊竞品全域监控专家」，为美国站竞品 [填入核心竞品 ASIN 列表] 建立持续监控档案并完成首轮基线采集（配送邮编 10001，币种 USD，保存至 [你的本地工作区路径]）。 【站内实时采集：接入我的自有 Bright Data API】 请按技能包内的 api-bridge.md 与 data-contract.md 规范，在包外工作区建立独立的 Python 标准库 bridge 脚本并保存 connection.md，供后续每轮直接复用： 1. 认证：从环境变量 BRIGHTDATA_API_KEY 读取，请求头 Authorization: Bearer <KEY>，仅访问 https://api.brightdata.com/datasets/v3/。 2. 实时抓取端点：POST https://api.brightdata.com/datasets/v3/scrape?dataset_id=gd_l7q7dkf244hwjntr0&format=json&include_errors=true 请求体：[{“url”:”https://www.amazon.com/dp/<ASIN>”,”zipcode”:”10001″}]（不要传 language 参数，避免触发 400 错误）。 3. 异步恢复：若超过 60 秒返回 HTTP 202 与 snapshot_id，保存 job.json 并轮询 /datasets/v3/progress/{snapshot_id}，ready 后从 /datasets/v3/snapshot/{snapshot_id}?format=json 下载结果，禁止超时重复提交。 4. 字段验收：输出 schema 2.0 的 normalized.json；若个别字段（如 Coupon）API 返回 null，允许按采集路由用当前浏览器对该缺项做一次定点核实补齐。同时调用已启用的 sellersprite-mcp 补充历史价格带、月销量估算与核心流量词背景，输出首轮监控报告与标准 CSV 表格。

不管选哪种方式，第一轮跑完后，本地都会生成一套标准监控档案文件夹（包含历史索引、接入记录、首轮基线报告与 CSV 表）

你也可以再让AI写进在线文档里，后续复跑都以这份档案为模板接着往下记。

4. 配置飞书或企业微信群推送

如果希望团队成员随时在线协同查看，直接在 WorkBuddy 的「连接器」里启用飞书 MCP 或企业微信 MCP 即可。

授权连接后，发送下面这段指令，让它按竞品监控报告的模块结构，一次性建好包含云文档与数据明细表的在线监控模版。

请调用已启用的飞书 MCP（或企业微信 MCP），作为我的「竞品监控文档维护助手」，基于刚生成的首轮监控档案（路径：[填入第3步生成的本地档案目录]），创建并初始化一套《亚马逊核心竞品持续监控台账》在线文档： 【 1. 明确职责与文档结构】 请根据本轮监控报告与 CSV 的实际内容，创建包含以下三个核心板块的在线云文档（支持多维表格/在线表格时，同步建立结构化数据表）： – 板块一「最新巡检看板（置顶）」：展示最近一轮的巡检时间、监控 ASIN 范围、一句话核心结论，以及本轮发生的价格变动、Coupon 上下线、BSR 波动、标题五点微调与已核实的站外促销线索。 – 板块二「多轮指标累计明细表」：对齐本地累计 CSV 的核心字段（巡检轮次、观察时间、ASIN、站点邮编、页面价格、优惠原文、可售状态、BSR 排名、评分、评论数、Buy Box 卖家、站外线索状态），将首轮基线数据完整写入表内。 – 板块三「历史巡检归档日志」：按日期倒序折叠留存每一轮的完整变动对照与卖家精灵市场背景解读。 【 2. 后续持续维护机制】 1.创建完成后，请返回在线文档的完整访问链接，并将该文档链接与文档 ID 写入本地工作区的`doc-sync-config.md`中保存。 2.后续每次执行新一轮巡检后，请读取该配置定位同一份在线文档（禁止每轮重复新建文档）：自动刷新顶部的「最新巡检看板」，在「多轮指标累计明细表」末尾追加本轮新记录（同轮不重复写入，缺失字段留空不拿旧值填充），并在「历史巡检归档日志」顶部插入本轮变化摘要。

5. 设置 WorkBuddy 自动化定时任务

本地档案模板和在线监控文档建好后，在 WorkBuddy 左侧栏点击【自动化】新建一个定时任务。

在任务配置面板里，先选定本地工作空间、勾选「亚马逊竞品全域监控专家」，并在 MCP 连接器里打开卖家精灵MCP和企业微信 MCP的开关，设置好执行频率（例如每天早上 8:00）。

接着把下面这套完整的端到端工作流提示词粘贴进去（大家使用时保留自己选用的那一条、删掉另一条即可）：

请调用「亚马逊竞品全域监控专家」，按以下完整工作流执行今日例行竞品巡检，并通过已开启的企业微信MCP持续维护在线监控台账： 【第一步：加载监控档案与到期检查】 读取本地工作区/在线文档监控档案：[填入本地档案文件或者在线文档链接]锁定监控对象（美国站US，配送邮编10001，币种USD）与已确认的子体规格，检查本轮到期的站内观察与站外复查范围，不覆盖历史快照。 【第二步：站内实时数据获取（以下两条路径二选一，使用时删掉不用的那条）】 – [路径 A：使用WorkBuddyComputerUse采集] 调用内置电脑/浏览器操作能力打开目标竞品页面，确认左上角配送地址为10001且显示USD，按十项核心字段清单采集当前新品价格、Coupon优惠原文、可售状态、类目BSR、评分、评论数、标题、五点描述、BuyBox卖家与父ASIN（遇验证码立即停止该页，不强行绕过）。 – [路径 B：使用自有BrightDataAPI采集] 复用本地工作区已建立的`api-connections/brightdata/`适配脚本（从环境变量BRIGHTDATA_API_KEY读取凭据），请求`gd_l7q7dkf244hwjntr0`实时抓取端点获取最新商品记录并转换为 schema2.0标准格式（超时返回202时轮询原 snapshot_id 恢复，禁止重复提交；若个别Coupon字段为null，允许用浏览器定点核实补齐）。 【第三步：补充卖家精灵MCP周期背景】 调用已开启的`sellersprite-mcp`，获取监控ASIN的历史价格区间、优惠趋势、月度销量估算与核心流量词背景，单独存入市场背景模块，辅助判断本轮调价或改词幅度，不拿周期统计值替代今日页面现价。 【第四步：公开站外推广线索核验】 结合目标ASIN、品牌名与折扣词检索公开Deals网站、评测站与论坛，复查历史已知活动并打开原帖核实落地商品与促销条件，按「已核实 / 候选线索 / 已排除」分档记录。 【第五步：同口径比对与本地文件沉淀】 核对配送邮编、币种与规格口径后，对比上一轮有效基线计算差异，提交生成本轮Markdown监控报告，并自动更新包外的`本轮标准字段.csv`与`累计标准字段.csv`（同轮去重，未检查字段留空，不填旧值）。 【第六步：通过企业微信MCP更新在线文档并推送】 读取本地`doc-sync-config.md`定位同一份企业微信在线文档《亚马逊核心竞品持续监控台账》（禁止新建文档）： 1.刷新文档置顶的「最新巡检看板」（更新本轮巡检时间、核心结论与关键变动项）； 2.在「多轮指标累计明细表」末尾追加本轮十项标准指标记录； 3.在「历史巡检归档日志」顶部插入本轮变化对照与市场背景解读，完成后通过已开启的企业微信通路同步本次更新摘要。

保存后先点一下「测试运行」确认全链路跑通，从第二天开始就会每天定时自动巡检了。

这套竞品全域监控SKill的配置，稍微有点复杂。
