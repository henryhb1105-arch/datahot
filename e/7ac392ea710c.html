原文

A comprehensive guide to pricing models, usage views, monitoring patterns, and cost governance for Cortex AI services

As organizations increasingly adopt AI-powered features within Snowflake, understanding how these services are priced, metered, and governed becomes critical. Snowflake’s AI ecosystem — spanning Cortex AI Functions, Cortex Agents, Cortex Search, CoCo, and more— uses a consumption-based model where costs scale directly with usage. Without proper observability, AI workloads can quietly accumulate significant spend.

This guide walks through the full cost lifecycle: how AI services are priced, where to find usage data, how to write monitoring queries, and how to enforce spending guardrails.

1. The AI Credit Pricing Model

Snowflake introduced AI Credits as a billing unit distinct from Platform Credits. This separation creates a consistent, edition-independent pricing layer — Standard, Enterprise, Business Critical, and VPS customers all pay the same AI Credit rate.

Pricing by routing type:

The routing type is controlled by the CORTEX_ENABLED_CROSS_REGION account parameter. If data residency is not a concern, global routing saves approximately 9% on every AI Credit.

AI Credits vs. Platform Credits

This is a critical distinction. A SQL query that calls AI_COMPLETE() incurs two separate charges:

  • AI Credits for the token processing by the LLM
  • Platform Credits for the warehouse compute time running the SQL query

Platform Credit pricing varies by edition and region. AI Credit pricing does not. They appear as separate line items in your billing.

What uses AI Credits:

Note: When Cortex Analyst is invoked through Cortex Agents (the recommended path), it follows the same token-based AI Credit model as Cortex Agents.

2. What Drives Cost in Each AI Service

The primary cost driver for most Snowflake AI services is token consumption. A token is the smallest unit of text processed — roughly 4 characters, though this varies by model.

Token-Based Services

AI Functions (AI_COMPLETE, AI_CLASSIFY, AI_EXTRACT, AI_EMBED, AI_FILTER, AI_TRANSLATE) are billed per million tokens, with rates varying by model. Both input and output tokens are billable for generative functions. Embedding functions (AI_EMBED, AI_SIMILARITY) only bill input tokens.

Cortex Agents orchestrate multi-step workflows. Their costs are additive across every tool they invoke. A single agent request that calls Cortex Search, then AI_COMPLETE, then Cortex Analyst accumulates charges from each step --- plus the orchestration layer itself consumes tokens.

Cortex REST API provides direct model inference with per-token billing. It supports prompt caching, where cache reads are billed at a reduced rate compared to standard input tokens.

Service-Based Pricing

Cortex Search has two billing components:

  • Serving compute: Credits per GB per month of indexed data, running continuously while the service is active
  • Embedding compute: Per token, charged when data is inserted or updated

AI Parse Document charges per 1,000 pages processed, with the rate varying by parsing mode.

Media Token Equivalents

The Hidden Cost Multiplier

Task-specific functions like AI_CLASSIFY, AI_FILTER, AI_SENTIMENT, and AI_SUMMARIZE_AGG append system prompts to your input text. The billed token count will be higher than the tokens in the text you provide.

More importantly: AI_CLASSIFY labels, descriptions, and examples are counted as input tokens for every record processed, not once per call. If you pass 10 classification labels with descriptions and process 100,000 rows, those label tokens are billed 100,000 times. This is a significant cost multiplier for large-batch classification jobs.

3. The Usage Views Architecture

Snowflake provides a layered system of views in SNOWFLAKE.ACCOUNT_USAGE and SNOWFLAKE.ORGANIZATION_USAGE for tracking AI consumption. Understanding this hierarchy is essential to avoid double-counting.

The View Hierarchy

METERING_HISTORY / METERING_DAILY_HISTORY  (authoritative billing totals)
│
├── SERVICE_TYPE = 'AI_SERVICES'           (legacy umbrella)
│   ├── CORTEX_AI_FUNCTIONS_USAGE_HISTORY    ← canonical for AI functions
│   ├── CORTEX_ANALYST_USAGE_HISTORY
│   ├── CORTEX_SEARCH_SERVING_USAGE_HISTORY
│   ├── CORTEX_DOCUMENT_PROCESSING_USAGE_HISTORY
│   └── CORTEX_FINE_TUNING_USAGE_HISTORY
│
├── SERVICE_TYPE = 'CORTEX_AGENTS'
│   └── CORTEX_AGENT_USAGE_HISTORY
│
├── SERVICE_TYPE = 'CORTEX_CODE_CLI'
│   └── CORTEX_CODE_CLI_USAGE_HISTORY
│
├── SERVICE_TYPE = 'CORTEX_CODE_SNOWSIGHT'
│   └── CORTEX_CODE_SNOWSIGHT_USAGE_HISTORY
│
├── SERVICE_TYPE = 'SNOWFLAKE_INTELLIGENCE'
│   └──SNOWFLAKE_COWORK_USAGE_HISTORY
│
├── SERVICE_TYPE = 'AI_INFERENCE'
│   └── CORTEX_REST_API_USAGE_HISTORY        (tokens only; billed in $)
│
└── SERVICE_TYPE = 'CORTEX_AI_GUARDRAILS'
    └── CORTEX_AI_GUARDRAILS_USAGE_HISTORY

Avoiding Double-Counting

Several legacy views overlap with the current canonical views:

  • CORTEX_FUNCTIONS_USAGE_HISTORY --- no longer updated. Use CORTEX_AI_FUNCTIONS_USAGE_HISTORY instead.
  • CORTEX_FUNCTIONS_QUERY_USAGE_HISTORY --- deprecated, slated for removal Nov 2026
  • CORTEX_AISQL_USAGE_HISTORY --- slated for deprecation Jan 2027

Use CORTEX_AI_FUNCTIONS_USAGE_HISTORY as the canonical view for AI function usage. Never sum overlapping views --- they share underlying metering data.

Latency Expectations

Account Usage views have up to 3 hours of latency, sometimes longer. Same-day queries may show gaps that resolve later. This is expected behavior. For authoritative billing totals, always use METERING_HISTORY or METERING_DAILY_HISTORY.

4. Practical Monitoring Queries

These queries use only official SNOWFLAKE.ACCOUNT_USAGE views and can be run as-is against any Snowflake account with the ACCOUNTADMIN role (or a role with IMPORTED PRIVILEGES on the SNOWFLAKE database).

4.1 Total AI Spend by Service Type (Last 30 Days)

Start here for a high-level view of where AI credits are going:

SELECT
    service_type,
    ROUND(SUM(credits_used), 2) AS total_credits
FROM SNOWFLAKE.ACCOUNT_USAGE.METERING_DAILY_HISTORY
WHERE service_type IN (
    'AI_SERVICES', 'CORTEX_AGENTS',
    'CORTEX_CODE_CLI', 'CORTEX_CODE_SNOWSIGHT',
    'SNOWFLAKE_INTELLIGENCE', 'CORTEX_AI_GUARDRAILS'
)
AND usage_date >= DATEADD('day', -30, CURRENT_DATE())
GROUP BY service_type
ORDER BY total_credits DESC;

4.2 AI Function Cost by Model

Identify which LLM models are driving the most spend:


WITH base AS (
    SELECT
        model_name,
        function_name,
        credits,
        metrics
    FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY
    WHERE start_time >= DATEADD('day', -30, CURRENT_DATE())
),
-- Credits aggregated on unflattened rows (no double-counting)
credit_agg AS (
    SELECT
        model_name,
        function_name,
        COUNT(*)              AS call_count,
        ROUND(SUM(credits), 4) AS total_ai_credits
    FROM base
    GROUP BY model_name, function_name
),
-- Tokens from flattened metrics, summing input + output explicitly
token_agg AS (
    SELECT
        model_name,
        function_name,
        SUM(f.value:"value"::NUMBER) AS total_tokens
    FROM base,
         LATERAL FLATTEN(input => metrics) f
    WHERE f.value:"key":"metric"::STRING IN ('input', 'output')
    GROUP BY model_name, function_name
)
SELECT
    c.model_name,
    c.function_name,
    c.call_count,
    COALESCE(t.total_tokens, 0) AS total_tokens,
    c.total_ai_credits
FROM credit_agg c
LEFT JOIN token_agg t
    ON c.model_name = t.model_name
   AND c.function_name = t.function_name
ORDER BY total_ai_credits DESC;

4.3 Top Users by AI Spend (Cortex Agents)

Attribute agent costs to individual users:

WITH request_tokens AS (
    SELECT
        h.user_name,
        h.request_id,
        h.token_credits,
        SUM(t.value:input::NUMBER)  AS input_tokens,
        SUM(t.value:output::NUMBER) AS output_tokens
    FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AGENT_USAGE_HISTORY h,
         LATERAL FLATTEN(input => h.tokens_granular) t
    WHERE h.start_time >= DATEADD('day', -30, CURRENT_DATE())
    GROUP BY h.user_name, h.request_id, h.token_credits
)
SELECT
    user_name,
    COUNT(DISTINCT request_id)      AS requests,
    SUM(input_tokens)               AS total_input_tokens,
    SUM(output_tokens)              AS total_output_tokens,
    ROUND(SUM(token_credits), 4)    AS total_ai_credits
FROM request_tokens
GROUP BY user_name
ORDER BY total_ai_credits DESC
LIMIT 20;

4.4 Daily AI Spend Trend

Detect cost spikes and patterns over time:

SELECT
    usage_date,
    service_type,
    SUM(credits_used) AS total_credits
FROM SNOWFLAKE.ACCOUNT_USAGE.METERING_DAILY_HISTORY
WHERE service_type IN (
    'CORTEX_AGENTS',
    'SNOWFLAKE_INTELLIGENCE',
    'SNOWFLAKE_COWORK',
    'CORTEX_CODE_CLI',
    'CORTEX_CODE_SNOWSIGHT',
    'SNOWFLAKE_COCO'
)
  AND usage_date >= DATEADD(MONTH, -1, CURRENT_DATE)
GROUP BY usage_date, service_type
ORDER BY usage_date;

4.5 Organization-Wide AI Spend

For multi-account organizations:

SELECT
    account_name,
    service_type,
    ROUND(SUM(credits_used), 2) AS total_credits
FROM SNOWFLAKE.ORGANIZATION_USAGE.METERING_DAILY_HISTORY
WHERE service_type IN (
    'AI_SERVICES', 'CORTEX_AGENTS',
    'CORTEX_CODE_CLI', 'CORTEX_CODE_SNOWSIGHT',
    'SNOWFLAKE_INTELLIGENCE'
)
AND usage_date >= DATEADD('day', -30, CURRENT_DATE())
GROUP BY account_name, service_type
ORDER BY total_credits DESC;

5. Per-Query Cost Attribution

The total cost of an AI query in Snowflake is the sum of AI token credits and warehouse compute credits. You can join usage views with QUERY_ATTRIBUTION_HISTORY on query_id to get the complete picture:

SELECT
    usage.query_id,
    usage.model_name,
    usage.function_name,
    SUM(usage.credits) AS ai_credits,
    MAX(attr.credits_attributed_compute) AS warehouse_credits,
    SUM(usage.credits)
        + COALESCE(MAX(attr.credits_attributed_compute), 0)
        AS total_credits
FROM SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY AS usage
LEFT JOIN SNOWFLAKE.ACCOUNT_USAGE.QUERY_ATTRIBUTION_HISTORY AS attr
    ON usage.query_id = attr.query_id
WHERE usage.start_time >= DATEADD('day', -7, CURRENT_DATE())
GROUP BY usage.query_id, usage.model_name, usage.function_name
ORDER BY total_credits DESC
LIMIT 20;
Reconciliation note: The sum of credits from granular usage views will not exactly match METERING_HISTORY totals. Usage views expose only a subset of underlying metering events. Use granular views for relative attribution and trend analysis; use METERING_HISTORY as the authoritative billing source.

Estimating Cost Before Execution

Use AI_COUNT_TOKENS to estimate token usage before running expensive AI queries:

SELECT AI_COUNT_TOKENS('ai_embed', 'snowflake-arctic-embed-l-v2.0', 'Summarize the quarterly revenue trends...');

AI_COUNT_TOKENS itself incurs only warehouse compute cost --- no additional token-based charges. This makes it practical for pre-flight cost checks on large batch jobs.

6. Cost Governance: Budgets, Quotas, and Alerts

Snowflake provides three mechanisms for controlling AI spend: resource budgets, per-user quotas, and alert-based monitoring. Each has different strengths in terms of granularity, enforcement speed, and flexibility.

Budget Support by Feature

Resource Budgets

Resource budgets define monthly credit limits for specific Snowflake objects. They use the tag-based cost attribution model and can trigger automated stored procedures at configurable thresholds.

-- Account root budget already activated; skip ACTIVATE()
-- Create a custom budget (if it doesn't already exist)
CREATE SNOWFLAKE.CORE.BUDGET IF NOT EXISTS ANALYTICS_DEV.COWORK_DEMO.AGENT_BUDGET();
-- Set a monthly spending limit
CALL ANALYTICS_DEV.COWORK_DEMO.AGENT_BUDGET!SET_SPENDING_LIMIT(500);
-- Add a Cortex Agent to the budget
CALL ANALYTICS_DEV.COWORK_DEMO.AGENT_BUDGET!ADD_SHARED_RESOURCE(
    'CORTEX AGENT',
    (SELECT SYSTEM$REFERENCE('CORTEX AGENT', 'ANALYTICS_DEV.COWORK_DEMO.RETAIL_INSIGHTS_AGENT'))
);
Syntax note: Budgets are class instances, not standard Snowflake objects. Use SHOW SNOWFLAKE.CORE.BUDGET INSTANCES IN ACCOUNT.

Shared Resource Budgets

Shared resource budgets track credit consumption broken down by team or cost center. Users are identified via tags, allowing separate budgets for different teams even when they use the same underlying AI feature.

For example, if both an engineering team and a finance team call AI_COMPLETE, separate budgets track each team's credits based on their tagged user identities.

Per-User Quotas

Per-user quotas set monthly and daily credit limits for individual users. When block enforcement is enabled, Snowflake automatically denies further AI requests for users who hit their limit.

-- Create a per-user AI quota
CREATE SNOWFLAKE.CORE.QUOTA IF NOT EXISTS ANALYTICS_DEV.COWORK_DEMO.AI_USER_QUOTA();

-- Set monthly per-user credit limit
CALL ANALYTICS_DEV.COWORK_DEMO.AI_USER_QUOTA!SET_PER_USER_LIMIT(300);
-- Set daily per-user credit limit
CALL ANALYTICS_DEV.COWORK_DEMO.AI_USER_QUOTA!SET_PER_USER_LIMIT(50, 'DAILY');

-- Add AI domains to the quota (covers AI functions, Cortex Agents, etc.)
CALL ANALYTICS_DEV.COWORK_DEMO.AI_USER_QUOTA!ADD_SHARED_RESOURCE('AI FUNCTION');
CALL ANALYTICS_DEV.COWORK_DEMO.AI_USER_QUOTA!ADD_SHARED_RESOURCE('CORTEX AGENT');

-- Enable block enforcement: automatically block users who hit the limit
CALL ANALYTICS_DEV.COWORK_DEMO.AI_USER_QUOTA!SET_BLOCK_ENFORCEMENT_ENABLED(TRUE);

Enforcement Timing

The latency difference is significant for fast-moving AI workloads. Per-user quotas provide near-real-time enforcement, while budgets are better suited for monthly governance with operational responses.

Alerting on Cost Anomalies

Combine Snowflake alerts with metering views for proactive monitoring:

CREATE OR REPLACE ALERT ANALYTICS_DEV.COWORK_DEMO.AI_SPEND_ALERT
    WAREHOUSE = COMPUTE_WH
    SCHEDULE = 'USING CRON 0 8 * * * America/Los_Angeles'
    IF (EXISTS (
        SELECT 1
        FROM SNOWFLAKE.ACCOUNT_USAGE.METERING_DAILY_HISTORY
        WHERE usage_date = CURRENT_DATE() - 1
          AND service_type IN ('AI_SERVICES',
              'CORTEX_AGENTS', 'SNOWFLAKE_INTELLIGENCE')
        HAVING SUM(credits_used) > 100
    ))
    THEN
        CALL SYSTEM$SEND_EMAIL(
            'ai_cost_alerts',
            'team@company.com',
            'AI Spend Alert',
            'Daily AI credit usage exceeded 100 credits yesterday.'
        );

ALTER ALERT ANALYTICS_DEV.COWORK_DEMO.AI_SPEND_ALERT RESUME;

7. Best Practices and Optimization

Right-Size Your Models

Different models have substantially different per-token rates. Using a large model when a smaller one suffices can mean a 10x cost difference. Match model capability to task complexity:

  • Classification / sentiment: Smaller models often perform comparably at a fraction of the cost
  • Complex reasoning / code generation: Larger models justify the premium with measurably better output
  • Embedding: Use purpose-built embedding models, not general-purpose LLMs

Optimize Token Usage

  • Keep prompts concise — — every token counts toward billing
  • Use AI_COUNT_TOKENS() to estimate costs before large batch runs
  • For the Cortex REST API, leverage prompt caching for repeated system prompts
  • Be aware that AI_CLASSIFY labels and descriptions are counted as input tokens for every record, not once per call --- restructure batches if possible

Warehouse Sizing for AI Workloads

Snowflake recommends using a warehouse size no larger than MEDIUM when calling Cortex AI Functions. Using a larger warehouse does not increase AI function performance (the LLM inference happens server-side), but it does incur unnecessary Platform Credit charges for the idle warehouse capacity.

Control Cortex Search Costs

  • Cortex Search serving runs continuously while the service is resumed — — suspend services when not actively needed
  • Monitor indexed data volume; costs scale with GB of indexed data
  • For one-time batch workloads, prefer Cortex Batch Search (charges only while the job runs, not continuously)

Enable Cross-Region Routing

If data residency is not a constraint, set CORTEX_ENABLED_CROSS_REGION = 'ANY_REGION' to pay $2.00 instead of $2.20 per AI Credit --- a flat 9% savings on all AI consumption.

Build a Cost Dashboard

Combine the monitoring queries above into a scheduled dashboard. Key panels to include:

  • Daily AI credit trend (stacked by service type)
  • Top 10 users by AI spend
  • Model-level cost breakdown
  • Budget utilization vs. limits
  • Week-over-week cost comparison

Establish a Review Cadence

  • Daily: Automated alerts for threshold breaches
  • Weekly: Review top users and model distribution to catch runaway patterns
  • Monthly: Reconcile metering totals against usage views, review budget utilization, adjust quotas
