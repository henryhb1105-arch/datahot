上周，我们举办了Claude Build Day，这是我们的最新黑客松，开发者们齐聚旧金山，使用 Claude Opus 4.8 将他们的想法付诸实践。

在我们等待他们成果的同时，我们与 Built with Opus 4.7 黑客松的获奖者聊了聊他们的项目。他们涉及医疗培训、电子维修、计算机科学教育、互动游戏、家庭维修和工厂维护。

祝贺所有获奖者和参与者！我们希望他们的想法能给你带来启发。

第一名：Medkit，Bedirhan Keskin

来自伊斯坦布尔的医生转软件工程师 Bedirhan Keskin 使用 Claude Managed Agents 构建了 Medkit：一个面向住院医师或初级医生的学习工具，在游戏化的医疗诊所中模拟真实患者接诊。

“当你独自在急诊室面对50个等待的患者，意识到有些病例你在医学院从未实践过时，你最终会在真实患者身上实时进行实践，”Bedirhan 说。

使用 Medkit，医学生可以练习诊断和治疗模拟患者，使用该工具采集病史、开实验室检查、读影像、诊断和制定治疗方案。最后，一个代理评分器会根据与考官相同的公开临床指南对整个过程进行评估。

Bedirhan 在四次独立的 Claude Code 会话中构建了 Medkit（语音引擎、内容生成、3D游戏层和核心应用），保持每个上下文干净，并同时推进所有部分。他遵循“说而非打字”的方法，几乎完全通过语音工作。

Medkit 已经获得关注，三个位于伊斯坦布尔的医学院和一家制药公司将在未来几周内开始试点。

给其他开发者的建议：把 Claude 当作思想伙伴，而不仅仅是编码代理。

Bedirhan 的第一直觉是自托管语音引擎，但 Claude 建议使用云提供商以加快进度。“我最看重 Claude 的是它不仅仅是代码生成器，而是一个思想伙伴，帮助我看到原本会忽略的选项，”他说。

第二名：Wrench Board，Alexis Chapellier

来自法国 Reignier-Ésery 的 Alexis Chapellier 在创建 AI 驱动的维修店管理平台RepairMind之前，曾多年修理电子产品。他的 Opus 4.7 黑客松项目Wrench Board帮助独立技术人员解决复杂维修问题。用户上传原理图和板卡视图并描述症状，代理会创建统一电气图，进行推理，指出要探测的确切焊盘，读取测量值，并更新假设，直到诊断出问题。

Alexis 在 Claude Design 中原型化了 Wrench Board，将应用职责分离（设计、原理图导入、板卡视图、诊断代理），并为每个职责先生成规格说明再制定计划。他在 Claude Code 的多代理模式下执行，调试时每步都通过并行运行五六个代理进行基准测试，每个领域一个专用代理。

Alexis 押注 Opus 4.7 理解可视原理图的新能力；他说当他让模型追踪主板上的电源路径时，他知道它起作用了。

“我看着 Wrench Board 的板卡视图一步步亮起，出现箭头，组件被指向，名称浮出。那一刻，我明白这个想法站得住脚，”他说。

Wrench Board 的下一阶段是建立一个对尝试该应用感兴趣的电子维修者社区，以及能够用现场经验丰富该工具的专家。他的 Claude 积分将用于 RepairMind、那些首批用户以及所有正在进行的基础设施。

“这次黑客松证明了从维修店出来的自学成才的人能在五天内交付一个雄心勃勃的系统，”Alexis 说，他在参加时还在申请“生存工作”。“Claude Code 放大了那些有想法并有毅力执行的人，无论起点如何。”

给其他开发者的建议：深入头脑风暴，并对模型提出质疑。

Alexis 使用Superpowers，一个集成到 Claude 中的技能框架，用于结构化的头脑风暴-计划步骤，有时并行进行头脑风暴以在不同方面取得进展。他从 Claude Design 开始，然后使用内置按钮将项目直接共享给 Claude Code，并在模型说“不”时推动它。

“在黑客松期间，Claude 多次告诉我这或那在可用时间内无法完成。实际上，我有充足时间，”他说。“你得知道怎么告诉它，我还是想试试。"

第三名：Maieutic，Paula Vásquez-Henríquez

Paula Vásquez-Henríquez 在智利康塞普西翁的德尔发展大学教授计算机科学，她说过去两年她看到越来越多学生通过了考试却不理解自己的代码。

“现在学生用 AI 制造代码，但完全不知道代码做什么，”她说。“他们从未学会准确表述问题，在编码前草拟计划，或批判性地阅读自己的代码并注意到它偏离了意图。自动补全在他们甚至还没想清楚问题之前就交付了可用代码，所以元认知循环——即真正造就程序员的思考自身思考——永远不会闭合。他们毕业时能生成代码，却不能推理代码。”

Paula目前正在攻读人工智能博士学位，研究方向是学生与人工智能的互动模式。她参加黑客松是为了从学生和教师两个角度解决这个问题。

Maieutic是一款IDE，旨在让学生在关键时刻放慢脚步。学生在编写任何代码之前，必须用通俗语言描述他们的程序应该做什么；Claude会提出有针对性的澄清问题，并保持编辑器锁定，直到规格足够详细，以至于一个有能力的程序员无需猜测就能实现它。

然后学生可以开始编写Python，但自动补全已关闭；聊天面板直接回答参考问题，但对推理问题的回应是反问而不是修正，拒绝替学生思考。

Intent-Diff Review是工具的核心，它让Claude将规格与最终代码进行比较，将每个差异分类为偏离、修正或错误，然后提出一个中立、非指责性的问题，促使学生自己解释问题。

对于教师，实时仪表板显示每个学生一行，附有一句认知摘要（例如，“写了三次规格，仍未考虑空输入”）。教师可以点击单个学生来监控他们与Claude的具体互动。Claude还可以分析整个群体，识别并呈现全班共有的误解，以便教师弥补这一差距。

黑客松结束后，休斯顿大学的研究人员联系了Paula，希望合著一篇论文。Paula正在将她的奖金积分用于进一步开发该工具。她说，黑客松那一周让她看到，理解问题与交付工具之间的鸿沟已经消失了。

“我是智利康塞普西翁的一名教育工作者，”她说，“我一周内交付了一个完整的全栈产品，因为工具让我保持在真正擅长的角色中，而它们处理其余部分。最接近实际问题的人现在可以直接为这些问题构建解决方案。”

给其他开发者的建议：先思考再构建。

这个项目是Paula亲身实践自己的哲学：先规格后构建。“Maieutic的存在是因为学生们直接跳入代码，而我之所以能把它做好，唯一的方法就是拒绝自己这样做。”她说。她花了整整两天进行纯思考工作，在写第一行代码之前创建了设计规格和技术规格。

“那两天的规格在当时感觉慢，黑客松中确实有立即开始发布的压力，但它们让剩下的时间进展迅速，”她说。

Opus 4.7最具创意使用奖：虚拟木偶剧场，Rene Hangstrup Møller

受Opus 4.7空间推理能力的启发，全栈开发者Rene Hangstrup Møller构建了虚拟木偶剧场，这是一个基于浏览器的应用，将网络摄像头视频和语音变成动态的互动木偶表演。一个实时动画木偶模仿用户的动作，而另一个由人工智能驱动的同伴木偶与用户闲聊；口头提示可以即时改变场景并生成3D道具。

Rene在整个流程中使用Claude：概念讨论、规划和代码编写，而他负责方向、架构、审查和决策。该应用基于Bun、Vite和TypeScript，使用MediaPipe手部追踪（在WASM中运行）和Three.js以60fps渲染3D木偶舞台。一个小型WebSocket服务器通过Anthropic SDK连接到Claude Opus 4.7，以驱动人工智能木偶的对话并即时生成3D道具，而语音则通过Web Speech API进行输入，输出使用ElevenLabs（浏览器语音合成作为后备）。Opus的空间推理能力通过基于截图的反馈循环进行精炼，处理视觉输出。

虚拟木偶剧场没有目标，除了开放式游戏，Rene说她对她的获奖项目没有产品计划。对她来说，这是关于学习和乐趣。“我和我的小儿子测试了它，他玩得很开心，”Rene说。“看着他与木偶互动、描述场景、为回应咯咯笑，这是我唯一需要的用户验证。”

虚拟木偶剧场的源代码可在GitHub上以MIT许可证获取，“如果有人想进一步发展它，”他补充道。

给其他开发者的建议：如果你参加黑客松，计划时间制作演示视频。

‍“制作一个3分钟的视频花费的时间比你想象的要长得多，”Rene说，并指出她使用Claude和Hyperframes在黑客松截止日期前创建和编辑了她的虚拟木偶剧场视频。“黑客松Discord中的很多人警告过这一点，他们是对的。下次，我会预留整个最后一天只制作演示。”

“持续思考”奖：MaestrIA，Benjamin Torralbo

Benjamin Torralbo从小跟随他的父亲Juan Rodrigo Torralbo学徒，他是一位经过认证的Maestro Mayor智利奇洛埃的木匠。“我的父亲有30年的手艺，修复过联合国教科文组织列出的教堂，但在智利体系中仍然隐形，像成千上万的其他工匠一样，”Benjamin说。“与此同时，需要房屋维修的人不知道哪里出了问题、花费多少、应该叫谁，以及收费是否合理。”

他的MaestrIA黑客松项目解决了双方的问题，它是一个网络应用，为普通民众提供大师级的家庭维修诊断，同时为熟练工匠提供展示专业技能的途径。

使用MaestrIA，用户拍摄问题照片，用语音或文字描述，并分享位置。Claude实时流式传输推理过程，在照片上添加动画边界框，然后提供结构化诊断：哪些损坏、材料、严重程度1-5、项目预算和时间估算。然后代理渲染附近按行业过滤的maestros地图，而第二个代理起草一条WhatsApp消息发送。

MaestrIA的技术核心是一个JSON文件，注入到每次诊断中，包含17条诊断规则、7种奇洛埃本土木材、16个当地交易行话术语、19个基准价格和9个常见工艺错误，这些全部来自Benjamin与父亲数小时的访谈。在不触碰系统提示的情况下，这一文件使他的评估分数提升了7个百分点（从74%提升到81%，对比人类大师的判断），这也是MaestrIA能够诊断出“雪松木墙板上的上升潮气”而非笼统的“木材损坏”的原因。

没有任何编程经验的Benjamin表示，他的角色是现场主管，监督Claude的技术执行。“在写任何功能之前，我让Claude Code设计规格、分阶段行动计划和安全模型：针对提示注入的输入净化、速率限制、来源验证，以及作为唯一事实来源的Zod模式，”他说，“然后我逐个diff审查每个功能。”

Benjamin希望MaestrIA能够发展出新建筑、五金店整合、正式预算、合同、审查和认证系统。最终，每个行业都将内置自己的Maestro Mayor，包括木匠、建筑师、水管工、电工和泥瓦匠。

他的奖金积分将用于开发应用程序，将父亲的公司作为实时试点进行数字化，以及促进自己的技术成长。“Claude Code让一位来自奇洛埃、没有编程经验的20岁年轻人能够构建出父亲可以使用的软件，并帮助智利28万像他一样的师傅，”他说，“这为数百万一直有宝贵想法却无法实现的人打开了大门。”

给其他开发者的建议：先评估，后功能。

“我做的最重要的一件事是构建了一个可审计的9维度评估，基于12个真实案例，并由我父亲记录真实情况，”Benjamin说，“正是这个评估，而不是我的直觉，告诉了我什么有效什么无效。如果我再次参加黑客马拉松，评估将是第一个提交。”

最佳Claude托管智能体应用：ARIA，作者：Idriss Benguezzou 和 Adam Hnaien

大多数工厂都有一位资深技术员，能仅凭声音判断机器何时会出故障。获得最佳Claude托管智能体应用奖的项目ARIA（自适应运行时智能）将经验丰富的维护工程师的直觉转化为一个价格实惠、设置快速的AI系统，持续监控工厂机器，并在问题出现时立即生成定制诊断和维修计划。

使用ARIA，维护工程师上传制造商的PDF，回答四个简单的语言校准问题，在15分钟内完成工厂配置。从那时起，五个智能体监控实时信号。如果智能体检测到故障或预测即将发生故障，它会生成包含组件、故障模式、紧急程度、零件和干预窗口分析的工作单。

该项目的两位构建者都有实地工业经验，他们在黑客马拉松的队友寻找Discord频道中相识。Idriss Benguezzou，一位拥有数据/人工智能硕士学位的法国工业软件工程师，已经构思了该想法及其大部分架构一段时间。Adam Hnaien，一位自学成才、熟悉Claude Code和多智能体工作流程的工科学生，立即认识到ARIA是工业维护的宝贵解决方案。

Idriss和Adam将黑客马拉松的第二天全部用于规划模式，使用GitHub项目板，在编写第一行代码之前确定每个里程碑、问题和验收标准。“我们希望从M2开始以200%的速度前进，”Adam说，“一天的规划让我们可以在接下来的一周执行，而不是即兴发挥。”

两人都估计Claude Code编写了约80%的原始代码行，而他们手动做出领域逻辑和设计决策。Idriss负责阈值评估、知识库模式和异常检测，因为他说：“你无法通过提示让代码知道维护技术员实际关注什么。”Adam负责用户体验、视觉语言和ARIA的星座概念，因为他说：“你无法通过提示获得品味。”

托管智能体处理了智能体基础设施。“如果没有Claude托管智能体，我们就会花一周时间构建Anthropic已经托管的基础设施：沙盒Python环境、安全执行、会话持久化、MCP调度，”Adam说，“相反，我们将那一周用于围绕该基础设施构建产品。这就是在五天内交付ARIA与在五周内交付ARIA之间的区别。”

黑客马拉松结果公布后，专门处理这一问题的公司联系了该项目。Idriss将把ARIA的智能体架构、知识库模式和信号管道整合到他自己的工业物联网平台中；他的积分将用于更多构建和实验。至于Adam，他的计划是继续探索工业智能体AI的机会，并使用API积分继续构建和实验。

给其他开发者的建议：让Claude审计。让Claude检查你已构建的内容是否有问题，然后再构建下一件事，Idriss说。“这个循环被低估了。”
