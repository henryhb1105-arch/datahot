# DataHot 第一阶段运营方案：连续 14 天达到 10 UV/日

## 目标

- 在统计链路上线后的 30 天内达到每天至少 10 个可测真实 UV。
- 连续 14 个完整 Asia/Shanghai 自然日，每天均不少于 10 UV，才判定第一阶段稳定达标。
- PV 是阅读深度的辅助指标，不用刷新页面制造 PV，也不以机器人或测试访问充数。

“可测 UV”指当天至少产生一次合法 `page_view` 的 30 天随机设备 ID 去重数。GPC、DNT、主动退出、未执行脚本的机器人和测试域名不计入，因此它是保守的设备近似值，不是实名人数。

## 最小增长飞轮

1. **内容供给**：现有流水线每天 4 次更新；每天从首页高质量候选中选择最多 5 篇不同文章，近 7 天已经发布的文章不重复使用。
2. **固定分发**：Bluesky 每天最多 5 个固定时段、每时段幂等发布一条；其中 1 条使用安全的文章图片卡片、其余为纯文本对照。纯文本中再轮换 1 条标题先行文案，品牌与序号移到链接行；链接仍直接落到详情页，同一时段重跑不会重复发帖。
   - GitHub Schedule 延迟超过 90 分钟时继续安全跳过；若自然重试后目标 rkey 仍不存在，运营任务可通过 SSH 推送唯一的 `growth-YYYY-MM-DD-slotN` tag 触发同一 Actions 发布链路。tag 必须指向已经包含本兜底 workflow、且提交说明不含 `[skip ci]` 等 GitHub 跳过指令的最新 `main` 祖先，workflow 内仍会 checkout 最新 `main` 数据。若主 tag 曾错误指向跳过提交、远端无对应 run 且 rkey 仍不存在，只允许新增一次 `-r1` 救援 tag；原 tag 不删除、不改指。两种 tag 都只在对应上海自然日有效，并与稳定 rkey 双重去重，不在本地读取 Bluesky 密钥，也不会增加第 6 条帖子。
   - 对外账号使用已验证的域名 handle `@datahot.xiahongbin.com`；域名通过 `/.well-known/atproto-did` 绑定长期 DID，迁移前后帖子与关注关系不变。
3. **承接体验**：详情页保持原文优先，页面可分享、可反馈；不为运营另加弹窗或注册墙。
4. **真实复盘**：后台按来源类型和热门页面判断“谁带来访客、访客读了什么”，下一周只保留带来真实 UV 的动作。

## 每日动作（10 分钟）

- 09:00：看昨日 UV 是否达到 10、主要来源、访问最多的三页。
- 09:05：确认当天候选值得分享，并检查前一天 5 个固定时段是否有重复、失败或异常降级。
- 18:00：若今日 UV 低于 7，先检查归因与落地页，不在 5 个固定时段之外临时补发或重复轰炸同一渠道。
- 23:00 后不再补量；次日按完整自然日复盘。

## 每周决策

- 社交来源每周带来至少 10 UV：保留当前 5 个固定时段，不继续增加频次。
- 至少完成一轮 5 天图片时段轮换后，按 `bluesky/card` 与 `bluesky/text` 的归因 UV/帖比较：图片稳定更高才扩大；没有提升则维持或停止图片实验。
- 至少完成 5 个完整发布日后，用唯一文章 `page_path` 对照标题先行与普通文本的 Bluesky 归因 UV/成功帖；标题先行连续更高才扩大，不能用点赞数代替站内 UV。
- 社交来源连续 7 天日均低于 2 UV：保持频次上限但停止机械扩量，优先调整标题、图片或渠道，不用更多帖子掩盖无点击。
- 搜索来源开始增长：优先强化已经有访问的主题页与详情页内部链接，不新建栏目。
- 某页面有 PV 无外链点击/反馈：先修内容承接，而不是继续买量或扩大分发。
- Henry 于 2026-09-05 明确批准使用已购买的 X API 做推广：取得可用的账号发帖授权后，即可开始每日最多 1 条单变量实验，无需等到第 7 日。缺少授权时只记录渠道缺口，不用自刷流量替代。

## X 推广：已获批准，等待连接验证

当前状态：**推广授权已取得，API 供应商、凭据位置、账号身份、写权限与余额仍待核对；尚未启用 X 自动发布。** “购买 API”不自动等于已有账号写权限，也不等于允许充值。此渠道与 #204 的只读产品雷达分开管理。

- 内容：优先数据产品设计库。每条聚焦一个实际设计问题，说明一个可借鉴的交互，直达对应案例步骤。没有新价值时跳过，不为凑数重复发帖。
- 起步频次：上海自然日最多 1 条，优先 18:07，与现有运营检查合并；Bluesky 仍独立最多 5 条。不回补历史日期、不额外发评论、私信、转发、点赞或关注。
- 文案：问题/结论先行，说明截图能证明什么；不把 DataHot 解读写成厂商原话，不把历史界面包装成最新产品。首轮纯文本加链接，不另购图像或媒体服务。
- 归因：链接使用 `utm_source=x&utm_content=text`，记录日期、账号 ID、案例 slug、唯一 page_path、文案、发布状态与成功 post ID。指标为真实 `x/text` UV/成功帖；点赞与曝光仅作辅助，不把直接访问算入 X。多帖复用同一落地路径时只能报告页面合计，不能伪装成单帖归因。
- 凭据：仅从已授权的本地安全存储或仓库加密 secret 读取，不输出密钥、不写到公开仓库。首次先用只读身份接口确认账号；仅有 app-only Bearer Token 时不尝试发帖。
- 成本：只使用已购余额，不启用自动充值、不购买广告、不扩大付费套餐。X 官方公开价格在核对日列出带 URL 的创建请求为 $0.20/次，1 条/日约 $6/30 日，另有少量读取成本；**以实际供应商和控制台价格为准**。授权、余额或费用边界不可确认时停止发送，不靠轮询反复消耗余额。
- 幂等门禁：启用发送器前必须有持久的日期/账号发布账本和单写者锁；发送超时或结果不确定时先核对账号时间线，不自动重复 POST。账号不匹配、权限错误、余额不足和读取失败均安全停止。
- 验收：本地模拟通过不算接入；需一次已授权正式精选发布、读回成功 post ID/公开内容、落地页 HTTP 验证，才标记该渠道已启用。不得为了验收制造生产 page_view。

参考：[官方认证边界](https://docs.x.com/fundamentals/authentication/oauth-2-0/application-only)、[官方价格与额度控制](https://docs.x.com/x-api/getting-started/pricing)。

### 设计案例归因覆盖

设计详情 `/cases/<slug>.html` 与比较页 `/cases/compare.html` 必须同时被客户端、离线 Python 和 Worker 路径校验接受，统一归入 `cases`；只保留公共相对路径，查询参数和锚点不入库。新增案例应由自动测试遍历 manifest 验证这条链路。修复前丢弃的事件不可估算回填，invalid 计数不能直接推断为某个页面的访问量。

## 四周推进

| 周期 | 重点 | 成功信号 |
|---|---|---|
| 第 1 周 | 上线可信统计；运行 Bluesky 5 时段图文对照 | 有 5 个完整统计日，来源、格式与热门页可解释 |
| 第 2 周 | 只优化带来访问的标题和主题 | 7 日平均 UV ≥ 5 |
| 第 3 周 | 对有效主题做一次周报式分享 | 至少 3 天 UV ≥ 10 |
| 第 4 周 | 固化有效渠道，停止无效动作 | 开始或完成连续 14 天 ≥ 10 UV |

## 禁止项

- 不购买不明流量、不自刷、不把监控探针算 UV。
- 不为统计采集 IP、指纹、完整 referrer、搜索词或个人身份。
- 未经单独确认，不自动向新的社交账号、群聊、邮件列表或联系人发内容。
- 看板无数据时显示“等待真实访问”，不得显示伪造的 0 或样例数据。
