Anthropic销售如何用Claude Code重构工作流

Anthropic的GTM产品经理Jared Sires在无编程背景下，使用Claude Code创建了CLAFTS工具，自动起草邮件回复，每天节省2-3小时。该工具在销售团队内部迅速传播，促使他转型为专注于用Claude解决方案优化销售流程的角色。他还开发了自动客户沟通、背景研究、会议纪要生成邮件等工具，并打包为Claude Cowork插件供团队使用。

一位 Anthropic 销售如何用 Claude Code 重建团队工作流程

在加入 Anthropic 之前，GTM 产品经理 Jared Sires 从未打开过终端。现在，Anthropic 销售团队使用他的工具。

在 2024 年加入 Anthropic 之前，Jared Sires 从未写过一行代码。他为什么要写呢？他是一名初创公司客户经理。

在快速成长的公司中常见的情况是，Jared 的客户名单很快增长到 600 或 700 个账户。每天有 10 到 15 个客户电话，加上不断扩大的账户列表，Jared 每晚都坐在办公桌前回复客户邮件直到 9 点或 10 点。

“管理收件箱几乎是不可能的，”他说，“再加上外呼，你真的不知道该关注哪里。”

Jared 求助于 Claude Code。没有编程经验的他创建了 CLAFTS，即 Claude Drafts 的缩写：一个运行在 Gmail 内的应用程序，使用 Claude API 起草客户邮件回复。经过多次迭代，最终 Jared 估计 CLAFTS 每天为他节省两到三个小时。第二天早上他在 Slack 上分享了它，24 小时内，销售组织的其他人开始使用它，也取得了类似的效果。

这导致了 Jared 在 Anthropic 的角色转变：如今，他是市场推广团队的产品经理，这个角色专注于识别 Anthropic 销售组织运营中的问题，并构建由 Claude 驱动的解决方案来解决这些问题。在这个新角色中，Jared 构建了自动化客户沟通的工具，在通话前研究客户背景，并从会议记录中生成后续邮件。然后他将这些工具打包为插件，放入 Claude Cowork，以便整个销售团队使用。

他形容自己职业生涯的转变是“我经历过的最赋能的事情”。

以下是 Jared 如何使用 Claude 大规模处理收件箱，他接下来正在构建什么，以及 GTM 团队可以从他的方法中借鉴的最佳实践。

一个深陷行政任务的销售代表

邮件数量并不是 Jared 作为客户经理面临的唯一挑战。Anthropic 每 24 到 48 小时就会发布产品变更，客户的问题往往集中在新细节上：批处理 API 的 SLA、提示缓存折扣、模型定价、SDK 行为。要回答好这些问题，意味着要搜索 Slack、Google Docs、内部知识库和开发者文档——并且日复一日地这样做，每次面对的事实都略有不同。

“必须向客户转述技术文档相当困难，尤其是在 Anthropic，产品发展如此之快，”Jared 说。

他最早用 Claude 做的实验之一既狭窄又实用。使用 Apps Script（Google 的轻量级开发平台）和 Claude，Jared 从内部系统中拉取产品使用数据，并让 Claude 每天早晨根据账户增长的速度对其排名。

“每天 Claude 都会给我一份简报，告诉我根据他们的使用情况，需要重点关注谁，”他说。在 700 个账户中，这份每日简报帮助他决定外呼时间投向哪里。

开发 CLAFTS

更大的挑战是 Jared 的收件箱，以及他不得不花在回复邮件上的深夜时间。

通过 Claude Code，他开始开发一个系统，以他的语气起草客户邮件回复。“Claude Code，末尾有‘Code’这个词，让我一开始就觉得有点吓人，”他说，“但过了一段时间，我理解了它连接我的电脑并回答文件相关问题的能力。”

CLAFTS 构建于大约 4300 行代码之上，几乎全部由 Claude Code 编写。它从共享的 Google Drive 文件夹和其他第三方工具中提取上下文，通过网络搜索引用 Anthropic 的公开文档，并匹配 Jared 的写作风格。当他在一天结束时打开草稿文件夹，回复已经等着他审阅了。

每当 Anthropic 发布产品变更，文档会反映出来，Claude 会在下一份草稿中获取变更。“Claude 能够使用网络搜索来理解我们网站上的最新文档，并在生成邮件时引用这些材料，”Jared 说，“我不需要把所有这些都记在脑子里。”

开箱即用时，Claude 的写作往往更长，且更多使用含糊的短语，所以 Jared 重写了系统提示词，直到草稿符合他自己的写作风格。“我可能经历了数百次 CLAFTS 的迭代，在系统提示词中调整以生成不同的写作内容，”他说。

接下来，他开发了 CLAFTS Tones 功能，该功能使用模式匹配来模仿他在不同关系中的语气。客户、同事和家人线程的读起来各不相同，草稿会相应调整。

Jared 通过在个人账户上给自己写一系列越来越愤怒的邮件来测试该功能。Claude 模仿了这种语气，然后拒绝继续。

“Claude 开始模仿那种语气，并且開始出現拒绝，因为 Claude 不想生成对客户的愤怒邮件，”他说，“那时我就知道 CLAFTS Tones 起作用了。”

衡量 CLAFTS 的影响

虽然 CLAFTS 每周为 Jared 节省 10-15 小时，但他最关心的转变是工作的准确性。由于 Claude 从文档中获取最新产品细节并用于每份草稿，客户收到的答案与最新发布的内容挂钩，而不是与 Jared 碰巧记住的内容挂钩。

“在 CLAFTS 之前，我感觉自己做的大多是行政工作，而不是花时间与客户在一起，”Jared 说，“有了 CLAFTS，我才能真正做更多我想做的事，那就是销售。”

扩展 Anthropic 的 GTM 工具包

除了Jared，BDR John Albert经常工作到午夜给客户发邮件，他也帮助共同构建了Clafts。当业务开发团队的其他成员看到他们的队友每天都能节省出时间后，他们也加入了进来。之后，他们自己做了大部分的推广工作。

Jared构建的下一套工具是一组技能，这些技能将他的日历两端连接起来：每日简报和每日总结。

每天早上，每日简报技能会读取他的日历，对将要会面的人进行网络搜索，并在第一次通话前生成谈话要点。该技能通过MCP服务器连接到Google日历和CRM数据，拉取每个客户的相关信息。

在一天结束时，每日总结技能会从Google文档和会议笔记中提取信息，起草后续电子邮件，类似于CLAFTS。

“你把这两者结合起来，就能让Claude管理你的日常任务，这基本上就成了一个代理，”他说。

Jared的工作现在进一步深入代理领域，因为他正在尝试使用Agent SDK并串联工作流程，让一次Claude运行的输出作为下一次运行的输入。

为了确保他使用Claude Code构建的工具能够在更广泛的团队中扩展，他通过Claude Cowork发布这些工具，将技能和MCP连接器打包成一个插件，任何人都可以在几分钟内安装。

在推出销售插件后的几个月内，Anthropic销售团队约有80%的人在使用它。剩下的20%主要是新员工，Jared认为这是下一个要解决的挑战，因为这些技能正是为了帮助人们更快上手而构建的。

在插件出现之前，每个新员工都要花数周时间摸索自己的工作流程。现在，新员工可以在第一天安装它，并拥有20多个技能，这些技能已经连接到他们使用的工具中：Salesforce、Intercom、Gong、Google日历、Gmail、Google Drive和BigQuery。

销售团队插件有两个核心技能：

  1. /customer-context 在大约90秒内从所有这些来源拉取360度的账户视图。
  2. /pipeline-management 会显示有风险的交易、预测指导和推进建议。

该软件包还集成了Cowork的调度功能，让销售代表可以排队自动运行技能。

“我们的销售人员可以回到有意义的对话中，而不是去更新所有这些不同的应用程序，”他说。

架构未来的方向

Jared的角色随着工具的变化而改变。作为GTM架构师，他现在参与产品工程师的设计讨论，并帮助为Anthropic的销售团队塑造新工具。

“我感觉随着技术壁垒的消除，我几乎能够设计更多的产品，并让资深工程师帮我实现到最后阶段，”Jared说。“我能够扩展并做更多事情。”

对于想知道是否能够构建类似东西的销售者，他的建议是打开Claude Code，找到一个拖慢自己速度的任务，并问Claude如何为它构建解决方案。

“如果你一年前告诉我，我将在Anthropic担任市场推广产品经理，我会非常惊讶，”他说。“我从来没有足够的技术能力参与这些对话。借助Claude，我能够设计和构建不仅改善我自己的日常工作流程，还改善整个团队工作流程的东西。我有空间进行更有创造性和战略性的工作，而且没有回头路了。”
