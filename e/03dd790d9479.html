AI 逐段翻译

您现在可以在Amazon Redshift 集群和 Amazon Redshift Serverless 工作组上使用 AWS IAM Identity Center 身份验证并启用增强型 VPC 路由。您的用户可以使用现有的企业凭证实现单点登录，并且身份验证流量通过 VPC 终端节点从您的虚拟私有云（VPC）内部发起，全程保持在 AWS 私有网络上。

我们在之前的文章中全面介绍了 IAM Identity Center 的集成情况，使用 AWS IAM Identity Center 集成身份提供商（IdP）与 Amazon Redshift Query Editor V2 和 SQL 客户端，实现无缝单点登录。该文章展示了用户如何通过 Query Editor V2 和第三方 SQL 客户端登录，以及他们的身份如何传播到 AWS 分析服务。

许多组织还要求此流量不经过公共互联网。增强型 VPC 路由会将您的集群与其他 AWS 服务之间的所有流量通过您的 VPC 发送，您可以使用安全组、网络 ACL 和终端节点策略对其进行管理，并在 VPC 流日志中进行观察。对于有数据驻留、监管或网络隔离要求的团队，这通常是强制性的。

在本文中，我们展示了新的 IAM Identity Center VPC 终端节点如何在启用增强型 VPC 路由时为身份验证流量提供私有网络路径。我们将逐步介绍终端节点设置，并验证从 Query Editor V2 和 SQL 客户端的流程。要使用此功能，您的 Amazon Redshift 集群必须运行补丁 204 或更高版本，并且您必须按照以下步骤创建 VPC 终端节点。

解决方案概览

当用户通过 Query Editor V2 或 SQL 客户端使用 IAM Identity Center 登录时，Amazon Redshift 不会简单地接受客户端呈现的令牌。它会使用 IAM Identity Center 验证该令牌，并在建立会话之前解析调用者的身份。这些调用来自 Amazon Redshift，而不是您的客户端，而增强型 VPC 路由会改变它们所采用的网络路径。

使用增强型 VPC 路由的身份验证流程

启用增强型 VPC 路由后，Amazon Redshift 对 IAM Identity Center 的调用会通过您的 VPC 传输，并遵循您的网络配置。流程如下：

  1. 用户通过 Query Editor V2 或 SQL 客户端登录，并通过 IAM Identity Center 向您的身份提供商进行身份验证。
  2. IAM Identity Center 颁发访问令牌，客户端在数据库连接时将该令牌呈现给 Amazon Redshift。
  3. Amazon Redshift 根据 IAM Identity Center OpenID Connect（OIDC）端点验证访问令牌，确认令牌的范围以及用户对 Amazon Redshift 应用程序的授权。它不会在未经验证的情况下信任客户端呈现的令牌。
  4. Amazon Redshift 再次调用同一个 OIDC 端点，将该令牌交换为针对 Amazon Redshift 的令牌。
  5. Amazon Redshift 调用 IAM Identity Center 身份存储来解析用户及其组成员资格。
  6. Amazon Redshift 将解析的身份映射到数据库身份，应用基于角色的访问控制，并建立会话。

下图说明了此身份验证流程，展示了 Amazon Redshift 对 IAM Identity Center 的每次调用如何通过接口端点穿越 VPC。

图 1：启用增强型 VPC 路由时的 IAM Identity Center 身份验证流程

如图中所示，步骤 3-5 表示 Amazon Redshift 通过您的 VPC 对 IAM Identity Center OIDC 和身份存储端点进行的调用。

由于没有公有 IP 地址的集群不使用互联网网关路由，因此 Amazon Redshift 默认情况下没有通往 IAM Identity Center 的路径。您可以通过为其所需的两个服务（IAM Identity Center OIDC 端点和身份存储端点）创建接口 VPC 端点来提供路径，这些端点通过 AWS PrivateLink 将流量保持在 AWS 网络上。

此解决方案涵盖以下步骤：

  1. 启用增强型 VPC 路由。
  2. 验证您的 VPC 上的 DNS 属性。
  3. 创建 IAM Identity Center 身份验证所需的接口 VPC 端点。
  4. 为 AWS Glue 和 AWS Lake Formation 创建接口 VPC 端点（可选，如果您查询数据湖或湖屋）。
  5. 创建 Amazon Simple Storage Service（Amazon S3）网关端点。
  6. 验证端点可用且使用私有 DNS。
  7. 使用 Amazon Redshift Query Editor V2 测试单点登录。
  8. 使用 Amazon Redshift JDBC 驱动程序测试 SQL 客户端的单点登录。
  9. 在 AWS CloudTrail 上验证调用。

前提条件

您应该具备以下前提条件：

  • 一个 AWS 账户，带有 Amazon Redshift 预置集群。Amazon Redshift Serverless 也支持增强型 VPC 路由，并且适用相同的端点，但您需要替换相应的工作组命令和设置。
  • 一个有效的 IAM Identity Center 与 Amazon Redshift 的集成，如使用 AWS IAM Identity Center 集成身份提供商（IdP）与 Amazon Redshift Query Editor V2 和 SQL 客户端，实现无缝单点登录所述。
  • 集群运行补丁 204 或更高版本，这是支持 IAM Identity Center 身份验证与增强型 VPC 路由的最低维护版本。
  • 在集群运行的 VPC 中创建 VPC 端点的权限，具体是ec2:CreateVpcEndpoint和ec2:DescribeVpcEndpoints。
  • 可选：同一 VPC 内的 Amazon Elastic Compute Cloud（Amazon EC2）实例，带有 SQL Workbench/J 和 Amazon Redshift JDBC 驱动程序 2.1.0.30 或更高版本及其依赖库，以测试 SQL 客户端流程。

操作指南

本文中的示例使用加拿大（中部）AWS 区域（ca-central-1）。将所有占位符值替换为您自己的值。

步骤 1：启用增强型 VPC 路由并关闭公共访问

要使用 Amazon Redshift 增强型 VPC 路由来控制网络流量，您需要在 Amazon Redshift 中启用增强型 VPC 路由。集群或工作组还必须不公开访问，这样到 IAM Identity Center 和其他服务的流量将通过您的 VPC 端点而不是互联网网关。按照启用增强型 VPC 路由中的说明，为新的预置集群或 Serverless 工作组启用它。对于现有集群或工作组，请执行以下步骤：

  1. 登录 AWS Management Console 并打开 Amazon Redshift 控制台，网址为 https://console.aws.amazon.com/redshiftv2/。
  2. 对于现有的预置集群 – 选择 属性 选项卡。
  3. 对于现有的 Serverless 工作组 – 选择 数据访问 选项卡。

在 网络和安全性 部分中，选择 编辑。

  1. 选择 启用增强型 VPC 路由 以通过 VPC 路由网络流量。
  2. 如果 启用公开访问 已启用，请清除它，以便集群或工作组不公开访问。

选择 保存更改。 以下截图显示了启用了增强型 VPC 路由并关闭公开访问的“网络和安全性”部分。

图 2：在 Amazon Redshift 中启用增强型 VPC 路由

注意： 当您更改增强型 VPC 路由时，Amazon Redshift 会自动重启集群。请在维护时段内进行此更改。

第 2 步：验证您的 VPC 上的 DNS 属性

私有 DNS 会将公共 AWS 服务主机名重定向到您的接口端点，并且它依赖于两个 VPC 属性。请执行以下步骤：

  1. 导航到 Amazon Redshift 并选择 属性 选项卡（适用于 Amazon Redshift 预置），或 数据访问 选项卡（适用于 Amazon Redshift Serverless）。
  2. 在 网络和安全性设置 下，选择关联的 VPC。
  3. 您的 VPC 详细信息将在新的浏览器选项卡中打开。
  4. 查看 详细信息 部分，其中这些属性显示为 DNS 主机名 和 DNS 解析。确保这两个属性都设置为已启用。以下截图显示了 VPC 详细信息页面，两个 DNS 属性均设置为已启用。

图 3：在 VPC 详细信息页面上启用了 DNS 主机名和 DNS 解析

  1. 如果任一属性为已禁用，请选择 操作，选择 编辑 VPC 设置，选择 启用 在您需要的属性上，然后选择 保存。以下截图显示了编辑 VPC 设置页面，您可以在其中启用这些 DNS 属性。

图 4：启用 DNS 主机名和 DNS 解析

第 3 步：为 IAM Identity Center 身份验证创建接口 VPC 端点

创建身份验证流程所需的两个接口端点。每个端点对应于前面描述的身份验证流程中的两个 IAM Identity Center 调用之一：

服务端点用途
com.amazonaws.<region>.sso-oauth验证和交换 IAM Identity Center 访问令牌
com.amazonaws.<region>.identitystore解析用户及其组成员资格

要为 AWS 服务创建接口端点

  1. 打开 Amazon Virtual Private Cloud (Amazon VPC) 控制台，网址为 https://console.aws.amazon.com/vpc/。
  2. 在导航窗格中，选择 端点。
  3. 选择 创建端点。
  4. 对于 类型，选择 AWS 服务。
  5. IAM Identity Center 是一项区域服务，因此这些端点必须能够到达您的 IAM Identity Center 实例所在的 AWS 区域。如果您使用的是 IAM Identity Center 多区域复制（您的实例已复制到您的 Amazon Redshift 集群运行所在的区域），请保留 启用跨区域端点 未选中。
  6. 对于 服务名称，搜索 sso-oauth 并为您的区域选择该服务（com.amazonaws.<region>.sso-oauth）。以下截图显示了创建端点页面的顶部部分，其中已选择 sso-oauth 服务。

图 5：创建接口 VPC 端点，第 1 部分

  1. 对于 VPC，选择您将从其访问 AWS 服务的 VPC。在我们的用例中，我们选择 Amazon Redshift VPC。
  2. 要启用 私有 DNS 支持，选择 其他设置 并选择 启用私有 DNS 名称。
  3. 对于 子网，选择要在其中创建端点网络接口的子网。每个可用区只能选择一个子网。您不能从同一可用区选择多个子网。有关更多信息，请参阅 子网和可用区。
  4. 对于 IP 地址类型，选择 IPv4。这会将 IPv4 地址分配给端点网络接口。仅当所有选定的子网都有 IPv4 地址范围且服务接受 IPv4 请求时，才支持此选项。
  5. 对于安全组，选择要与端点网络接口关联的安全组。在本文中，我们选择了与 Redshift 关联的默认安全组。以下截图显示了端点的 VPC、子网和安全组选择。

图 6：创建接口 VPC 端点，第 2 部分

  1. 对于 策略，要允许所有主体对接口端点上的所有资源执行所有操作，请选择 完全访问。要限制访问，请选择 自定义 并输入策略。此选项仅当服务支持 VPC 端点策略时才可用。有关更多信息，请参阅 端点策略。
  2. （可选）要添加标签，请选择添加新标签并输入标签键和标签值。
  3. 选择 创建端点。以下截图显示了创建端点之前的策略和标签设置。

图 7：创建接口 VPC 端点，第 3 部分

重复步骤 1-14 以创建身份存储端点，搜索 identitystore 并为您的区域选择该服务（com.amazonaws.<region>.identitystore）。

上述步骤中有两个设置很重要：

  • 启用私有 DNS 名称必需的。Amazon Redshift 解析公共服务主机名，例如，oidc.<region>.amazonaws.com。私有 DNS 是将该主机名指向您的接口终端节点的机制，因此流量保持在您的 VPC 内部。
  • 使用集群的安全组，因为集群是调用方。终端节点的安全组必须允许来自集群的端口 443 上的入站 HTTPS。当集群的安全组已经允许来自自身的流量时，复用集群自身的安全组是最简单的方法。专用安全组需要一条明确的来自集群安全组的端口 443 入站规则。

（可选）要使用命令行创建接口终端节点

  • create-vpc-endpoint（AWS 命令行接口（AWS CLI））。
  • New-EC2VpcEndpoint（适用于 Windows PowerShell 的工具）。

步骤 4（可选）：为 AWS Glue 和 AWS Lake Formation 创建终端节点

仅当您的集群通过 AWS Glue 数据目录和 AWS Lake Formation 查询外部数据时，才需要完成此步骤。常见示例包括 Amazon S3 Tables（Amazon S3 的一项功能）以及向 Lake Formation 注册的数据湖。如果您只需要单点登录，可以跳到步骤 5。Amazon Redshift 调用 AWS Glue 数据目录来枚举数据库和表，并调用 AWS Lake Formation 来检查权限和为基础数据发放临时凭证。与身份验证调用一样，这些调用由集群发起，因此在启用增强型 VPC 路由后，它们会通过您的 VPC 传输，并需要自己的路径。

对以下服务重复步骤 3 中的第 1–14 步：

  • com.amazonaws.<region>.glue。
  • com.amazonaws.<region>.lakeformation。

有了这些终端节点，Amazon Redshift 会将外部目录操作（如列出外部表）通过 VPC 终端节点而不是公共互联网进行路由，从而使元数据流量保持在 AWS 网络内。

步骤 5：创建 Amazon S3 网关终端节点

启用增强型 VPC 路由后，集群针对 Amazon S3 执行的任何操作（COPY、UNLOAD 和 Amazon S3 Tables）也会通过您的 VPC 传输。创建一个网关终端节点，并将其与集群子网使用的路由表关联：

  1. 打开 Amazon VPC 控制台，网址为 https://console.aws.amazon.com/vpc/。
  2. 在导航窗格中，选择 终端节点，然后选择 创建终端节点。
  3. 对于 类型，选择 AWS 服务。
  4. 对于 服务名称，搜索 s3，并选择您所在地区具有 类型：网关（com.amazonaws.<region>.s3）的服务。以下截图显示了已选择 Amazon S3 网关服务的“创建终端节点”页面。

  1. 对于 VPC，选择您的 Amazon Redshift VPC。
  2. 对于 路由表，选择与集群运行的子网关联的路由表。
  3. 选择 创建终端节点。以下截图显示了 S3 网关终端节点的 VPC 和路由表选择。

图 9：创建 Amazon S3 网关终端节点，第 2 部分

步骤 6：验证终端节点

在 Amazon VPC 控制台中确认您创建的每个终端节点都可用，并且接口终端节点上已启用私有 DNS。

  1. 打开 Amazon VPC 控制台，网址为 https://console.aws.amazon.com/vpc/。
  2. 在导航窗格中，选择 终端节点。
  3. 在终端节点列表中，使用过滤器栏按 VPC ID（选择 VPC ID并选择您的 Amazon Redshift VPC）进行筛选。然后找到您为本演练创建的终端节点：sso-oauth、identitystore、Amazon S3 网关终端节点，以及（如果创建了）glue和 lakeformation。
  4. 确认每个终端节点显示 状态为 可用。
  5. 选择每个 接口终端节点（sso-oauth、identitystore、glue、lakeformation），并在 详细信息选项卡上，确认 已启用私有 DNS 名称为 是。以下截图显示了完整的终端节点列表，每个终端节点都处于“可用”状态。

图 10：在本演练中创建的 VPC 终端节点，处于“可用”状态

步骤 7：使用 Amazon Redshift Query Editor V2 测试单点登录

  1. 在 Amazon Redshift 控制台上，选择“查询编辑器 v2”。
  2. 选择您的集群，然后选择“IAM Identity Center”作为连接方法。
  3. 在提示时使用您的公司凭据登录。
  4. 在树视图中展开集群，以列出数据库、模式和表。

数据库列表会在几秒钟内填充。通过查询连接日志来确认服务器端的登录。请以不使用 IAM Identity Center 的用户身份运行此操作，例如使用密码的数据库用户，或通过 Amazon Redshift Data API 运行：

SELECT record_time, user_name, auth_method, driver_version, remote_host, event
FROM sys_connection_log
WHERE auth_method LIKE '%Idc%'
AND record_time > dateadd(minute, -15, getdate())
ORDER BY record_time DESC;

成功的登录会显示 user_name为 <idc_namespace>:<user@example.com>，以及 event为 authenticated，这确认了身份是通过您创建的终端节点解析的。以下截图显示了 sys_connection_log 查询结果，其中每次 IAM Identity Center 登录都显示 user_name为 <idc_namespace>:<user@example.com> 格式。

图 11：使用 IAM Identity Center 连接的查询编辑器 V2，显示数据库列表

步骤 8：使用 SQL 客户端测试单点登录

从 VPC 内 EC2 实例上的 SQL 客户端进行测试是更强大的验证，我们建议两者都做。Query Editor V2 通过 Amazon Redshift 托管代理连接，因此其连接记录为回环地址。VPC 内运行的客户端直接连接到集群端点，这正是您创建的端点所服务的路径。

设置 SQL Workbench/J

SQL Workbench/J 通过 Amazon Redshift JDBC 驱动程序连接。在与集群位于同一 VPC 的 EC2 实例上，下载并安装 SQL Workbench/J。

  1. 下载最新的 Amazon Redshift JDBC 驱动程序及其依赖库，并将存档解压到实例上的一个文件夹中。
  2. 启动 SQL Workbench/J，并选择 文件，然后选择 管理驱动程序。
  3. 选择“创建新条目”图标，并在“名称”中输入 Amazon Redshift。
  4. 对于“库”，选择文件夹图标，并选择驱动 JAR 文件以及依赖库文件夹中的每个 JAR 文件。在列表中只保留一个驱动版本，并删除任何以前的条目。
  5. 选择文件，然后连接窗口，并选择“创建新连接配置文件”图标。输入配置文件的名称，例如redshift-idc。
  6. 对于“驱动”，选择您创建的 Amazon Redshift 驱动。

  8. 将“用户名”和“密码”留空。浏览器插件将交互式地获取身份。

步骤 9：验证 AWS CloudTrail 中的调用

您可以从 AWS CloudTrail 中确认这些调用通过您的接口端点而非互联网传输。每个事件都包含一个vpcEndpointId字段，指明调用经过的端点，以及一个vpcEndpointAccountId字段，标识拥有该端点的账户。

com.amazonaws.<region>.identitystoreidentitystore.amazonaws.comDescribeUser、ListGroupMembershipsForMember、BatchDescribeGroup

  • 身份存储 API 调用（DescribeUser、ListGroupMembershipsForMember、BatchDescribeGroup）记录在拥有您的 IAM Identity Center 实例的账户中。事件源是identitystore.amazonaws.com。如果您在委派管理员或管理账户中使用集中式实例，则这些事件会出现在该账户中，而不是在运行集群的账户中。即使在身份验证正常工作时，搜索集群自己的账户也一无所获。要确认要查找的账户，请运行aws sso-admin list-instances并检查OwnerAccountId。

清理

为避免产生未来费用，请删除您为本演练创建的资源。这些端点在启用增强 VPC 路由时提供单点登录的网络路径，因此只有在不再需要该集成时才将其删除。

  • 在 Amazon VPC 控制台上，选择“端点”。
  • 选择您创建的 sso-oauth 和 identitystore 接口端点，然后选择“操作”，再选择“删除 VPC 端点”。
  • 选择 glue 和 lakeformation 接口端点（如果您已创建），并删除它们。
  • 选择 Amazon S3 网关端点并删除它。这也会移除其路由表条目。
  • 终止您用于测试 SQL 客户端连接的 EC2 实例（如果您为本演练创建了实例）。
  • 如果您不再需要该集成，请移除 Amazon Redshift 的 IAM Identity Center 应用程序分配，并删除关联的 IAM 角色和策略。

结论

在这篇文章中，我们向您展示了如何在启用了增强型VPC路由的集群上为Amazon Redshift启用AWS IAM Identity Center身份验证。您的用户可以使用企业凭证进行单点登录，并且身份验证流量在您的VPC内保持私有。关键概念是，由Amazon Redshift（而不是您的客户端）验证访问令牌。由于已启用增强型VPC路由，Amazon Redshift通过您的VPC路由该验证调用。在运行补丁204或更高版本的集群上，sso-oauth和identitystore的接口终端节点为Amazon Redshift提供了通过AWS PrivateLink的私有路径。为AWS Glue、AWS Lake Formation和Amazon S3添加终端节点可将相同的好处扩展到数据湖和湖仓查询。

在您自己的环境中尝试此设置，并在评论中让我们知道您的想法。有关更多信息，请参阅以下资源：
